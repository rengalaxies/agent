## Исправленное поведение

PR-сравнение раньше использовало прежний список потребителей удалённой операции: новый вызов мог потеряться, удалённый вызов продолжал вызывать предупреждение, сохранённый вызов был STALE. Теперь сравнительный анализ повторно сопоставляет разрешённый текущий код с полным базовым каталогом операций и проверяет результат по текущим декларациям. Новый/перенесённый/сохранённый вызов получает CURRENT и цитату текущей версии; удалённый/статически перенаправленный вызов не сохраняется как текущий риск. Непроверяемый исторический вызов остаётся STALE с явным историческим текстом.

Один разрешённый вызов снимает только свой unmapped_call, с точностью до столбца. Соседний неизвестный вызов, неоднозначность, динамические параметры и недоступные исходники остаются видимыми. Сохранённые base/head контексты не меняются. На управляемом удалении операции: сравнительный PR получает3 текущих потребителей и проверенные базовые декларации, а отдельный head-скан честно остаётся PARTIAL/3 unmapped_call. Сравнительная полнота означает полноту в статическом профиле и разрешённом корпусе; совместимость и runtime не доказаны.

Удаление доказывается по всем разрешённым репозиториям сервиса поставщика, на обеих версиях. Неполный базовый каталог, недоступный второй repo, неподдерживаемые регистрации и новые непрозрачные Python-основания не превращаются в доказанное удаление. Полное удаление доступного provider-файла остаётся поддержанным случаем. На уровне сервиса один подтверждённый текущий вызов сохраняет ACTIVE; исторические свидетельства не помечаются текущими, несколько текущих callsites объединяются.
