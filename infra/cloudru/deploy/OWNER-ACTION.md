# Единственный обязательный пакет действий владельца перед P1

**Граница:** Cloud.ru project `20853297-65b7-42a8-af40-25c8d2df4e11` ("Даниил Смирнов"). Чужие проекты научного руководителя не трогать.

## 1. Cloud.ru: подготовка хранилища Terraform State

В выбранном проекте создать отдельный **закрытый** бакет Object Storage с именем, начинающимся на `dmrp-tfstate-daniil-` (суффикс уникален). Включить версионирование; запретить анонимный/публичный доступ всеми четырьмя ограничениями Public Access Block. Добавить тег `cloudru_project_id=20853297-65b7-42a8-af40-25c8d2df4e11`. Владелец должен проверить проект в интерфейсе: сам тег не доказывает владение.

Создать отдельную пару S3 Access Key / Secret Access Key с минимальными правами на бакет и префикс `terraform/p1/` (операции чтения, записи, удаления, перечисления и создания блокировочного файла). Это **не те же** `CLOUDRU_KEY_ID` и `CLOUDRU_SECRET`, которые уже используются провайдером. Не отправлять ключи в чат или в GitHub Issues.

Документация: https://cloud.ru/docs/s3e/ug/topics/api__getting-started
и https://cloud.ru/docs/s3e/ug/topics/api__methods

## 2. GitHub: заполнить шесть параметров один раз

Открыть https://github.com/rengalaxies/agent/settings/secrets/actions

В Repository secrets:
- `CLOUDRU_STATE_ACCESS_KEY_ID` - S3 access key из шага 1.
- `CLOUDRU_STATE_SECRET_ACCESS_KEY` - S3 secret key из шага 1.
- `CLOUDRU_SSH_PUBLIC_KEY` - собственный реальный SSH public key (начинается `ssh-ed25519` или `ssh-rsa`; закрытый ключ остаётся на устройстве владельца).
- `CLOUDRU_UI_BASIC_AUTH_HASH` - хеш bcrypt пароля для доступа к демонстрационному сайту (исходный пароль владелец сохраняет вне GitHub).

В Repository variables:
- `CLOUDRU_STATE_BUCKET` - точное имя бакета из шага 1.
- `CLOUDRU_ADMIN_CIDR` - конкретный доверенный публичный IP администратора в формате `a.b.c.d/32`, не `0.0.0.0/0` и не тестовые сети.

`CLOUDRU_STATE_S3_ENDPOINT` заполнять **не требуется**, используется официальное `https://s3.cloud.ru`. Регион `ru-central-1` - значение по умолчанию.

Пароль для UI можно получить и хешировать с помощью команды `caddy hash-password` на своём защищённом компьютере. Никогда не помещать исходный пароль или приватные ключи в переменные, где ожидается public key или bcrypt hash.

## 3. Защитить однократный запуск

При необходимости в https://github.com/rengalaxies/agent/settings/environments создать environment `cloudru-p1-production` и включить Required reviewers. Workflow дополнительно требует явного `workflow_dispatch`, полного project UUID, суммы одобрения и фразы `AUTHORIZE-PAID-DEPLOYMENT`. Никакого автоматического `apply` на `push` нет.

**Пока ничего не запускать** в workflow `cloudru-apply-protected.yml` и не подтверждать оплату. Когда GitHub secrets/variables заполнены, сообщить в чат только **"Доступы настроены"** без каких-либо значений. Ассистент перепроверит https://github.com/rengalaxies/agent/issues/9 и https://github.com/rengalaxies/agent/issues/10, а затем представит итоговую сумму и попросит отдельное согласие на создание ресурсов.

## Проверенные и ограниченные границы P1

Terraform Plan: 16 создаваемых ресурсов для двух ВМ и сети; UI `gen-2-4`, ядро `gen-8-32`, SSD 30+80 GiB, один прямой публичный IP UI, один sNAT. UI содержит синтетические сценарии, реальный V2 development API и отдельный распределённый E4-прогон в трёх процессах на **одной приватной ВМ**. Это **не** три отдельных облачных ВМ и **не** промышленная PostgreSQL-версия. Ни реальные пользовательские данные, ни E3 oracle не используются.

Предварительная смета около 8,3 тыс. ₽/30 дней с 25% резервом предполагает UI 720 ч, ядро 160 ч и не включает LLM. Рабочий таймер автоматически выключает ядро через 8 часов после загрузки, но **не является жёстким месячным лимитом** и не заменяет контроль биллинга Cloud.ru. Реальная цена будет зависеть от потребления.
