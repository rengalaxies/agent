# Продуктовый интерфейс: локальный синтетический стенд

Python 3.12, запуск из checkout репозитория:

```bash
python -m pip install -e '.[api,test-api]'
PYTHONPATH=src python -m change_completion.demo_web --state .runtime/product-web --port 8081
```

Открыть http://127.0.0.1:8081. Команда выполняет настоящий ограниченный SQL-переход из [примера](README.md), сохраняет результат и запускает отдельный продуктовый UI. Старый исследовательский UI не используется. Fixtures синтетические; срок разрешений примера ограничен, это не бессрочная клиентская конфигурация.

Скопировать локально нужный токен из `.runtime/product-web/demo-credentials.json` в поле доступа. Файл приватный; не публиковать его или базы состояния. Токены не выводятся в консоль и не сохраняются браузером. `analytics-owner` и `audit-owner` принимают свои компоненты; `business-acceptor` принимает пакет после обоих владельцев. `demo-worker` читает результаты, проверяет актуальность и повторно открывает актуальный пакет после устаревания. Для смены роли нажать "Забыть токен".

## Что проверять

1. Открыть переход: цель, уровень критичности, владельцы, приемщик и границы обследования.
2. Посмотреть компоненты и неизвестные зависимости. Статический checkout не доказывает отсутствия внешних потребителей.
3. Открыть изменения и проверки: analytics получает diff 30→90, audit остается без изменения; четыре случая исполнены реальным ограниченным SQLite runner.
4. Принять каждый компонент соответствующим владельцем, затем пакет приемщиком. Отклонение блокирует передачу. Решения привязаны к digest конкретного пакета.
5. Подготовить PR или уведомление. Это устойчивый черновик; кнопки реальной отправки в примере выключены.
6. Изменение исходника, ожиданий, fixtures, runtime или полномочий делает результат устаревшим при чтении либо очередной проверке таймера (по умолчанию каждые 5 секунд). Согласования сбрасываются, неотправленные сообщения отменяются. Возвращение старых bytes не восстанавливает согласования автоматически: нужна явная повторная проверка и новые решения.

Журнал исполнения и журнал согласований хранятся отдельно в `runs.sqlite3` и `workflow.sqlite3`. Принятие пакета не выполняет merge, production deploy или отключение старого пути. Таймер работает, пока запущен сервер; внешнего фонового сервиса пока нет.

## Собственная установка

`python -m change_completion.web_server --help` показывает обязательные operator-owned пути. Repository содержит только кандидатские исходники; transition, expectations, fixtures, trust, identities и state размещаются вне него. Сервер слушает только loopback; удаленный доступ требует отдельного TLS/SSO и эксплуатационного проектирования. Это локальный прототип, не готовый production IAM.

Файл identities задает серверные роли, например:

```json
{"identities":[{"token_env":"PRODUCT_OWNER_TOKEN","actor":"analytics-owner","transitions":["your-transition-id"],"permissions":["read","review","prepare_delivery"]}]}
```

Секрет берется из переменной окружения, минимум 32 символа. Клиент не может назначить себе actor в запросе. Права интерфейса не заменяют grants на действия над компонентами.

Доставка по умолчанию отключена. Для opt-in нужен `--delivery-config`: `config` с endpoint, exact `allowed_endpoints`, `allow_send:true` и при необходимости `key_env`; `repositories` сопоставляет component_id адресу назначения PR, `notifications` - actor адресу уведомления. Также нужны отдельное право `send_delivery` и действующие grants PUBLISH_PR/NOTIFY. Прямого GitHub/GitLab/почтового адаптера пока нет: используется утвержденный клиентский HTTP gateway.

Gateway получает JSON с kind, payload и idempotency_key; должен обеспечивать дедупликацию и вернуть тот же ключ и receipt с external_id и HTTPS url. Подготовка и отправка - разные действия. Внешние redirects запрещены. Протокол реализован в `delivery.py`, проверен локальным HTTP-сервером, а не клиентской интеграцией.

Состояния outbox: PENDING → SENDING → DELIVERED либо UNKNOWN. После неопределенного ответа или прерывания SENDING автоматического повтора нет: оператор сверяет внешний результат по ключу. Повтор уже доставленного задания возвращает receipt. Exactly-once внешнего эффекта не обещается; отзыв полномочий после последней проверки не может атомарно отменить уже начинающуюся внешнюю отправку.

## Проверено и не проверено

Пачка 4: 31 новая автоматическая проверка; общий набор - 255 успешных тестов. Проверены API, серверные роли, последовательность приемки, устаревание без событий источника, черновики, запреты отправки, дедупликация и неопределенный исход. Локальный сервер запущен. HTML/JS проверены статически; визуальный браузерный прогон не выполнен: в среде отсутствует Chromium. Реальные клиентские PR/уведомления не отправлялись. Резервирование, восстановление, offline образ и квалификация поставки относятся к следующей пачке.
