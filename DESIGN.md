# HTTP graph demo interface

Scope: `src/agent_graph_demo/web`, the separate HTTP application prescribed by PR29. The existing `ui/` research examples remain a different historical product surface; its canned ACCEPT/REJECT components are unsuitable for this evidence workflow.

Use a quiet light inspection workspace for daytime laptop demonstrations: warm white canvas, dark ink, restrained deep teal for actions, amber for risks, red for failed checks. Typography is a readable system sans; monospace is limited to exact source and diagnostics. No decorative illustrations or invented metrics.

The main heading names the task. A compact state strip distinguishes proposed source from running service. A three-column desktop workspace gives the dependency map, change/impact/check story and exact evidence their own stable positions. At 390px these become sequential sections without horizontal page overflow; source/diff can scroll inside their own boxes.

Graph edges are actual CLI-discovered records, represented by labelled direction and keyboard buttons. A small SVG draws the selected relationship; no predetermined graph map. Static facts, human/model proposals and runtime checks occupy distinct sections.

Buttons use a visible focus outline, disabled and loading states, action verbs in Russian. History opens saved artifacts and marks them historical. Source always uses textContent. Freshness is the time of the last explicit assessment, not a claim that polling rescanned files.
