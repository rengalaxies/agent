## Три разные оценки

**Протокол.** Успешно наблюдались 20 HTTP 200, структурированные JSON ModelReply и разрешённые `read_source`/`propose`. Один запрос остался без статуса из-за timeout. После первой диагностики Qwen соблюдала null-поля действия, но не fidelity цитат. Native function calling не использовался и не квалифицирован: продукт работает с конечным JSON-протоколом действий, а native `tool_calls` исходный адаптер отклоняет. Ни один investigate не достиг `COMPLETED/finish`: исходный строгий критерий `protocol_passed` остаётся false для всех случаев. Дополнительный `transport_action_protocol_passed` означает лишь совместимый обмен HTTP/JSON/action; он не превращает отклонённую цитату в успешный цикл. У GPT Export это также не означает корректные аргументы инструмента.

**Качество предложений.** По первоначальному oracle 0/6 прошли критерий полного обоснованного результата. Там, где предложение появилось, Qwen угадала две положительные связи, GPT правильно различила сервисы в отрицательном контроле. Qwen перепутала направление/сервис в Status. Ни у одной модели это не стало точным проверенным предложением. Отсутствие принятого ложного ребра нельзя выдавать за правильность всех модельных гипотез: часть была неверной и заблокирована раньше. Предложения/их смысл проверены отдельно от формального key-based score; `quality.forbidden=[]` в машинном отчёте относится к принятым кандидатам, не доказывает отсутствия ошибочных модельных утверждений.

**Валидатор.** Scope, capability, свежесть/basis, диапазоны и точные цитаты проверялись существующим ядром. Кавычки не нормализовались, пропущенные отступы не восстанавливались автоматически, ложные цитаты не заменялись правильными. Не приняты ни неверная связь, ни неточные основания для правдоподобной связи. Принятие кандидата означало бы только UNAPPROVED_CANDIDATE, а не техническое ребро, одобрение требования или разрешение выпуска.

## Что исправлено и что остаётся

Переиспользованы `ChatModel`, `investigate`, `get_evidence`, `Graph.propose`, source collector/extractor, SQLite reserves и OS-lock. Изолированный patch для закреплённого кандидата добавляет безопасный observer и проверенное продолжение уже выполненных чтений, нумерованные строки в результатах чтения и документированный `max_completion_tokens` для точного endpoint Foundation Models. Guardrails ядра сохранены. Весь patch и его digest доступны в manifest каждого запуска.

Первоначальный адаптер передавал `max_tokens`. [Официальный пример Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/guides__llm-chat-request) использует `max_completion_tokens`; последние два случая GPT проверены с этим параметром, максимумом 4096 и request deadline 60 секунд (предел ядра). Поддержка `reasoning_effort` в документации Cloud.ru не подтверждена, этот параметр не добавлялся. Исправление имени параметра не доказывает причину предыдущего timeout. Нельзя утверждать, что backend соблюдал legacy-параметр на запросе без ответа; его usage остаётся неизвестным.

Стабильная проблема текущего JSON-протокола — модель пересоздаёт текст цитат вместо точного копирования. Нумерация помогла строке, но не кавычкам/отступам. Следующая обоснованная локальная работа: протокол ссылок на неизменяемые evidence IDs/диапазоны, с разрешением цитат доверенным кодом через тот же scope/basis/quote validator, без автоматического ремонта отвергнутого вывода. Перед новым live экспериментом нужны отдельные предзарегистрированные критерии и перенос уже израсходованного бюджета; текущий пакет закрыт и не делает новых вызовов. Остаток 19 запросов не является командой его расходовать.

## Расходы и ограничения измерения

- Уникальные request IDs: **1…21 без пропусков/повторов**. Все исторические запросы, включая диагностику и timeout, перенесены в ledger. Не складывайте `requests` отдельных runs: поздние отчёты включают историю, такое сложение даст двойной счёт.
- По случаям: 5/3/4/3/2/4 запросов, каждый ≤6; максимальное суммарное активное исполнение случая — около 54,2 секунды. Паузы ручного офлайн-разбора между ранними Qwen продолжениями отдельно и не названы модельным execution time. Модельные действия последовательны, автоматических retries нет.
- Ограничение времени имеет существенную оговорку: для раннего Qwen Reporting 300 секунд считались по сумме активного исполнения между продолжениями. Сквозное wall-clock время между первым и последним продолжением превышает пять минут из-за ручной диагностики. Поэтому этот случай не подтверждает соблюдение строгого единого пятиминутного wall-clock окна; последующие отдельные случаи укладывались в него. Это ограничение методики сохранено, а не скрыто за суммой времени запросов.
- Максимум запрашиваемых выходных токенов — 4096. Наблюдённых `finish_reason=length` нет; timeout не позволяет судить об окончательном ответе провайдера. Резервы не возвращались после ошибок. Контекст/корпус/строки/полномочия и денежный corporate guard сохранены.
- Qwen: **15115 input + 2259 output**, estimate **2,395226 ₽**.
- GPT: **9093 input + 2042 output наблюдено**, estimate известной части **0,26877698 ₽**; usage одного timeout-запроса не получен.
- Всего известно **24208 input + 4301 output**, оценка **2,66400298 ₽ плюс неизвестный расход timeout-запроса**. Это арифметическая оценка без счёта/проектного биллинга, налоговых/кэш/грантовых поправок и округления отчётного периода.

Оценка использует опубликованные ставки [официального каталога](https://cloud.ru/products/evolution-ai-factory/catalog-foundation-models), проверенные 21 октября: Qwen 122/244 ₽ за миллион input/output, GPT 15,86/61 ₽. Формальное тарифное приложение при получении ответило timeout; доступные источники и это ограничение указаны в README. Фактический биллинг — `NOT_MEASURED`; отсутствие usage не заменялось нулём. Покрытие грантом принято из явного подтверждения владельца, повторное подтверждение не запрашивалось.
