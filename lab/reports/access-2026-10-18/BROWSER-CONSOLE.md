# Браузерная консоль при повторном отказе SSH

Сейчас управление ОС уже подтверждено через pinned SSH; выполнять эти команды для повторения проверки не требуется.

Если SSH снова пропадёт: в личном кабинете Cloud.ru выберите проект `20853297-65b7-42a8-af40-25c8d2df4e11` → «Виртуальные машины» → `dm-p1-ui` (ID `c9e589fc-a42a-4cc3-8038-fe7d73929713`) → «Виртуальная консоль». Войдите существующим `dmadmin`. Пароль сюда не присылайте, не сбрасывайте и ВМ не пересоздавайте.

Введите по одной строке — символ `|` не нужен:

```sh
date -u
hostname
ip -br address
ip route
sudo ss -lntp
sudo ufw status verbose
sudo iptables -S
sudo nft list ruleset
ssh-keygen -l -E sha256 -f /etc/ssh/ssh_host_ed25519_key.pub
```

Ожидаемые идентификаторы: hostname `dm-p1-ui`, `enp3s0` UP, адрес `10.0.0.6/24`, default via `10.0.0.1`; Ed25519 `SHA256:UU9PJMk1+AXNkUwrfAsYaBc2Zeq4g/6vbf84IvCv3SU`. Не подменяйте pin при несовпадении.

Для поддержки откройте существующее обращение и проверьте последний ответ. Добавление подготовленного SUPPORT-REQUEST.md относится к той же заявке; не публикуйте ключи/пароли/state.

Firewall не отключать. Для установления места потери пакета нужны одновременные ограниченный TCP-пробник runner и `tcpdump` на `enp3s0` в консоли с фактическим source IP и UTC конкретного запуска — отдельный старый снимок tcpdump без временной корреляции причину не доказывает.
