# Пакет 1: надёжный контур карты и решений

Статус: реализован и проверен. Семантические режимы и пороги H1 не изменены. Формат хранения - knowledge-ledger-2. E3 и межпроцессный E4 не проводились.

## Ревизия и изменения

| Пробел до пакета | Что изменено | Проверка |
| --- | --- | --- |
| Решения существовали только в памяти координатора | Терминальные решения сохраняются в общем файле с картой и снимками; индексы восстанавливаются из журнала | Новый экземпляр и отдельный Python-процесс возвращают точный прежний результат |
| Другой run_id или proposal_id мог повторно разрешить то же изменение | Ключ разрешения зависит от продукта и полного содержимого старого/нового контрактов | Один COMMITTED; следующие корректные запуски - ALREADY_COMMITTED с прежним release_id |
| Одна целевая версия могла получить разное содержимое | Отдельный индекс product_id + new_contract_version | Второй несовместимый вариант - ABORTED без release_id |
| Ответ COMMITTED мог предшествовать надёжной записи | Сначала запись временного файла, fsync, атомарная замена и fsync каталога; затем возврат результата | Ошибка сохранения не возвращает разрешение; экземпляр блокируется до повторной загрузки |
| Два экземпляра могли перезаписать изменения друг друга | Файловая блокировка на сохранении и сравнение хеша версии файла | Устаревший экземпляр отклоняется; чужая запись сохраняется |
| Проверка хешей не доказывала соответствие сохранённого решения механизму | При восстановлении заново строятся снимки и решения на историческом контексте, сверяются доказательства, причины и состояние | Повреждённая трасса отклоняется даже после пересчёта её хешей |
| Недействительный атрибут мог участвовать в доказательстве нарушения | Применимые требования проверяют также действительность связанных атрибутов; дубликаты атрибутов закрывают допуск | Отозванный атрибут + нарушение формулы дают NEEDS_REVIEW, а не ложное доказанное нарушение |
| Журнал мог получить события задним числом | Запрещено убывание времени решений и изменения записей до уже сохранённого события выпуска | Попытки отклоняются без новой записи |
| Причины были в основном кодами | Представления содержат контракты до/после, consumer/field/obligation/evidence и пояснения причин | Проверено представление потребителя |

COMMITTED означает сохранённое разрешение на выпуск. ALREADY_COMMITTED - служебное состояние повторного запуска с тем же ранее разрешённым изменением, а не дополнительное семантическое решение. Enum решений по-прежнему ACCEPT/REJECT/NEEDS_REVIEW; ABORTED относится к жизненному циклу.

Повтор прежнего run_id возвращает исторический результат даже после последующих изменений карты. Это воспроизведение прежнего решения, а не новое разрешение в текущем контексте. Для нового контекста используются новые снимок и run_id.

## Журнал решений и публикаций

Событие решения содержит sequence, previous_hash, event_hash, время, fingerprint запроса, миграции и полный MappedRelease. В MappedRelease фиксируются proposal/run/snapshot, семантическое решение, состояние, release_id, определения контрактов, доказательства, причины и трасса состояний.

Восстановление проверяет: формат и checksum файла; историю владельцев/версий/времени; соответствие подтверждающего участника событию и полномочиям; снимки относительно исторических записей; порядок и цепочку событий решения; воспроизводимость решения; уникальность разрешения изменения и целевой версии. При проблеме хранилище не выдаёт новое разрешение.

| Операция | Назначение |
| --- | --- |
| release_journal() | Проверенная копия истории решений и подтверждений публикации |
| pending_publications() | Разрешения, для которых ещё нет подтверждения публикации |
| acknowledge_publication(release_id, evidence_ref, at) | Сохраняет факт подтверждения с источником; повтор с тем же источником идемпотентен, конфликт запрещён |
| GET /runs/{run_id} | Возвращает сохранённое решение |
| GET /release-journal | Возвращает журнал |
| GET /publications/pending | Возвращает ожидающие подтверждения разрешения |
| POST /publications/{release_id}/ack | Подтверждение от уполномоченного производителя |
| CLI journal / pending / ack | Те же операции для автономной работы с файлом |

Примеры:

```sh
PYTHONPATH=src:. python examples/knowledge/recovery_demo.py
PYTHONPATH=src python -m datamesh_release_protocol.knowledge_cli \
  --authorities examples/knowledge/authorities.json --ledger /path/to/ledger.json journal
```

## Границы гарантий

Реализована однократность **разрешения**, а не внешней публикации данных. Компонент не выполняет публикацию продукта. Получатель должен дедуплицировать release_id; при сбое после внешней публикации и до ack возможна повторная доставка. Запись ack - свидетельство оператора/адаптера, а не автоматическое доказательство внешнего действия. Перед фактической публикацией адаптер должен учитывать актуальность контекста; старое разрешение в pending не заменяет такую проверку.

Хранилище использует POSIX flock/fsync и ориентировано на Linux-стенд с локальной файловой системой. Блокировка защищает сохранение, но не превращает JSON-файл в распределённую БД. Второй писатель должен повторно загрузить актуальный журнал. Поведение NFS, отказ диска, авария питания и реальная устойчивость конкретного облачного тома отдельно не проверялись.

Хеши и повторное вычисление выявляют повреждения и несогласованные артефакты. Они не заменяют защищённые файлы, криптографические подписи и подтверждение истинности доменного знания. Изменение семантического интерпретатора после freeze требует версии и миграционного решения; восстановление не подстраивает исторические результаты под новые правила.

## Проверка и следующая зависимость

105 unittest-тестов пройдены. В них 22 проверки нового контура восстановления и надёжности; дополнительно расширена проверка API. Structural evaluation-check: 10 тестов без запуска режимов на evaluation-каталоге. Проверены повторный запуск в отдельном Python-процессе, ошибки до и после замены файла, защита от устаревшего писателя, подмена доказательств, подтверждения публикации и понятные представления.

Пакет 1 закрыт. Следующая автономная пачка - пакет 2: независимые доменные процессы, транспорт, TTL, fault injection, адаптеры и инженерные проверки E4. Экспертная разметка остаётся условием основного E3.
