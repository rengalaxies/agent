# Русское Jira-представление среднего объёма — 08.11.2026

Запрос владельца: сохранить основную суть и полезные ограничения, убрать полотно
служебных версий, пустых секций и полного текста Confluence. Системные формулировки
на русском; не сводить полезную находку к одной строке. [Предпросмотр](PREVIEW.md)
сгенерирован локально на сохранённых результатах PR4, в Jira не публиковался.

## Реализация

В конфигурации Jira появился явный opt-in: `"comment_format": "summary_ru"`.
По умолчанию `full`, чтобы не менять существующие коннекторы/приёмочные сценарии.
Для Bitbucket→Jira используется та же настройка Jira. Полный ResultView document,
включая Confluence-текст/версии/основания, остаётся в outbox; AnalysisResult в jobs
не меняется. Jira ADF выбирает только дополнительное `jira_summary` представление.
GitHub и DirectorySink сохраняют полный provider-neutral документ.

В кратком представлении: русский вывод, потребители/команды, изменённая операция,
путь и callsite, действия и существенные ограничения. Пустые секции не показываются;
вместо Confluence dump — название, версия, ссылка и пределы использования. CURRENT
с точным временем, correlation/code/schema/profile IDs и поколения не дублируются
в видимой версии. Одна служебная marker/digest строка остаётся для идентичности
и восстановления публикации: этот PR не меняет протокол идемпотентности.

Источники STALE/UNAVAILABLE, неполное покрытие, неизвестные ожидания и отсутствие
тестов не объявляются успешной проверкой. ABSTAINED/no_supported_delta не означает
отсутствие любого влияния. Service-level calls не превращаются в выдуманный маршрут.
Проверки каждого потребителя, места вызова и требования сохраняются; встроенные
английские шаблоны переведены детерминированно. Произвольная нестандартная рекомендация
источника сохраняется цитатой на языке источника, а не угадывается переводчиком.

Модельные гипотезы/квалификационные отказы пока сохраняют полный формат даже при
summary_ru: независимый значимый риск нельзя потерять ради сокращения. Модельный
путь этим изменением не включается. Будущая адаптация свободного модельного текста
не заявляется как реализованная часть этой пачки.

## Совместимость и раскатка

Старые queued intents без jira_summary отображаются по прежнему документу. Новый
формат появляется при новом/повторном анализе; смена только настройки не переписывает
старые receipts или историю. Для обновления существующих комментариев при раскатке
нужна отдельная контролируемая повторная обработка, не ручное редактирование Jira.
На целевой ВМ всё ещё опубликованный c4053c6; этот PR её не меняет. После CI/принятия
потребуются новый immutable release и published acceptance перед обновлением ВМ.
