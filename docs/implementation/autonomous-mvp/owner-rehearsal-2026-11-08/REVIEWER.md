# Лист разбора — открыть после собственных ответов

Это чек-лист владельца, не независимый oracle и не результаты измерения.
Первые ответы не перезаписывать: последующие уточнения писать отдельно.
Если ведущий подсказал ответ, отметить assisted; не считать такой пункт самостоятельным.

| Задание | Что должно быть различено |
| --- | --- |
| A | Orders удаляет прежний маршрут при переименовании; Reporting client.py:14 вызывает старый /orders/summary. Есть pinned code evidence, но runtime-тест не выполнен, owner неизвестен |
| B | Маршрут восстановлен; текущий PR diff пуст. Тот же native comment10046, новый head773000a и более новое поколение. ABSTAINED/no_supported_delta означает отсутствие классифицированной delta в профиле, не доказанную полную безопасность |
| C | Явная ссылка из описания KAN-9, Confluence page360725 version4. Это атрибутированный текст; требования не сопоставлены автоматически с кодом и не становятся подтверждённым oracle |
| D | Health200 — liveness. Во время контролируемого proxy fault есть reconcile_failed/outcome_unknown; нельзя объявить источники доступными. После снятия fault notice очищен, body комментария не менялся |

Оценки каждого пункта: clear / partial / unclear / assisted. Уверенность пользователя
не заменяет правильность. Человеческий ответ и оценку записывает человек.
Пока responses.template.csv пуст — ни одного результата владельца не получено.
Нельзя вычислять FP/FN или экономию времени: четыре задания проверяют понимание
одного авторского цикла, а не detection quality на независимой выборке.

Для настоящего M4/M5 нужны отдельный участник и независимые данные/ожидания до
просмотра ответов по [INDEPENDENT](../../../product/pilot/INDEPENDENT.md).
Новые численные пороги этот чек-лист не вводит; использовать действующий
