# Технические решения автономного MVP

Решения исполнителя внутри границ задания. Продуктовые решения владельца
записаны в `docs/product/pilot/DECISIONS.md` и `TRACKING.md`; здесь их не
пересматривают. У каждого решения есть причина и способ проверки.

## D1. Один контракт выдачи `agent-graph-output` 2.x

24.10.2026, пачка 2А. Код: `src/agent_graph/output_contracts.py`,
схема: `schemas/agent-graph-output-2.json`.

- Документы `analysis_request` и `analysis_result` несут `schema` и
  `schema_version` вида `major.minor`. Читатель отвергает другую major и более
  новую minor. Причина: один релиз поставляет и ядро, и приложение (5А), так
  что более новая minor означает смешанную установку, а не нормальную работу.
- Неизвестный код статуса, причины, delta, finding, usage, gap или unknown
  даёт `ContractError("unknown_code")`. `display_verdict` показывает такой
  документ как `INCOMPATIBLE` и никогда как зелёный.
- `reason_code` допустим только из набора своего статуса (`REASONS`).
- Утверждение `fact` требует хотя бы одного основания с provenance `AUTHENTIC`,
  достаточностью `SUPPORTED_WITHIN_PROFILE` или `OBSERVED_WITHIN_WINDOW` и
  происхождением не от модели. Гипотеза модели не может объявить себя
  достаточной. Это исполняет требование «модель не подтверждает свой кандидат».
- Происхождение, provenance, достаточность и свежесть — разные поля.
- `USEFUL` — предварительная классификация сервиса; поле
  `usefulness_confirmed` всегда `false`.
- Идентичность операции: `sha256([installation, environment, service, METHOD, route])`,
  та же формула, что `operation_id` ядра; route нормализуется (`//` и
  завершающий `/`). Имена параметров маршрута не нормализуются: это изменило
  бы существующие ID без измеренной пользы.
- Диагностика ошибок валидации содержит только путь поля и тип ошибки.
  Ключи словарей, не являющиеся именами полей, заменяются на `*`: ключи
  `text_fields` и `repository_revisions` приходят извне и могут содержать
  секрет.
- JSON Schema генерируется из моделей (`python -m agent_graph.output_contracts`);
  тест падает при расхождении. Семантические правила в JSON Schema не
  выражаются и проверяются только кодом; это записано в `description` схемы.

## D2. Windows — платформа разработки, Linux — платформа сервиса

24.10.2026, пачка 2А. Исходное ядро использует `fcntl` и `openat`-подобное
чтение (`O_NOFOLLOW`, `dir_fd`), которых нет на Windows. Все исполнители
задания работают на Windows без Linux VM, поэтому без переносимости ни один
тест ядра не запускается локально.

Решение: различия ОС собраны в `src/agent_graph/portable.py`. На Linux код
тот же, что раньше (`flock`, `openat` с `O_NOFOLLOW`, проверка битов `0o077`).
На Windows: `msvcrt.locking`, отказ от reparse point в каждом компоненте пути
и сверка `st_ino/st_dev` до и после открытия, без проверки битов режима.
Windows-путь уже POSIX-пути и не является границей безопасности; сервис
поставляется только на Linux (5А).

Окружение: при `core.autocrlf=true` Git на Windows выписывает фикстуры с CRLF,
и проверки дайджестов корпуса падают. Рабочее дерево исполнителя выписано
заново с `git -c core.autocrlf=false checkout`; конфигурацию репозитория не
меняли.

Проверка на Windows, коммит портирования: `tests/graph` — 137 из 139.
Два оставшихся падения вызваны средой, не кодом: создание symlink требует
привилегии (`WinError 1314`), и Windows не даёт удалить открытый файл SQLite
при очистке временного каталога (`WinError 32`). Оба теста должны проходить на
Linux CI; это проверяется в PR.

## D3. Анализ по закреплённым Git-коммитам

24.10.2026, пачка 2А. Код: `src/agent_graph/git_sources.py`, `sources.py`.

- Репозиторий с `snapshot: git` читается только из объектов коммита. Коммит
  берётся из карты запроса или из полного SHA в конфигурации; ветки, `HEAD` и
  сокращённые SHA отвергаются (`revision_required`). Причина: строка
  revision раньше ничего не доказывала (ADR-004).
- Коммит принимается, только если он достижим из `allowed_refs` этого же
  репозитория (`for-each-ref --contains`). Иначе — пробел `commit_unavailable`
  и PARTIAL; подмены на текущую ветку нет. Для репозитория PR сборщик
  результата делает из этого `FAILED commit_unavailable`.
- Каждый commit, tree и blob хешируется заново. Файл принимается, только если
  он достижим от закреплённого коммита по проверенным ID. Стоимость — чтение
  деревьев через `cat-file`, без `ls-tree`; на стенде это доли секунды.
- Git запускается без global/system config, с `GIT_NO_LAZY_FETCH`,
  `GIT_NO_REPLACE_OBJECTS`, отключёнными fsmonitor и hooks. Checkout не
  выполняется, поэтому фильтры и атрибуты репозитория не участвуют.
- Symlink, submodule, LFS pointer, бинарный файл, файл больше лимита и
  отсутствующий объект — видимые пробелы с путём.
- Режим рабочего дерева сохранён как есть и помечается
  `worktree_not_reproducible` в выдаче 2.0. Идентификатор view для старых
  конфигураций не меняется, чтобы не потерять сохранённую память.

## D4. Шум отделён от неподдержанных вызовов

24.10.2026, пачка 2А. Раньше любой вызов `.get/.post/...` становился
`unknown_http_client`, включая декораторы `@app.get(...)` у провайдера и
`dict.get`. Серия 22.10 видела эти ложные пробелы в задании модели. Теперь
пробел появляется, если получатель — импортированная HTTP-библиотека, объект,
созданный ею, имя вида client/session/http/api, или аргумент похож на URL или
путь. Каждый файл получает `file_coverage`: `EXTRACTED`, `UNSUPPORTED_CALLS`,
`PARTIAL_DECLARATIONS`, `UNPARSED`, `NO_DEPENDENCY_SIGNALS`, `NOT_CODE`.
Эвристика по имени может пропустить вызов через объект с нейтральным именем;
такой вызов остаётся вне грамматики, как и раньше.

## D5. Протокол `actions-v3` и исполняемая конституция

24.10.2026, пачка 2А. Код: `actions.py`, `constitution.py`, `executor.py`,
`constitutions/agent-service-v1.yaml`.

- Одно типизированное действие на ответ вместо плоского объекта с
  обязательными `null`. Схема для модели, системный шаблон и исполнитель
  строятся из одних pydantic-моделей; тест сверяет имена действий во всех
  четырёх местах. Старые протоколы `quotes-v1` и `evidence-refs-v2` не
  тронуты: на них записана история серий.
- Схема для провайдера «переносимая»: только ключевые слова, общие для
  строгих JSON-режимов. Границы длин проверяет исполнитель на слое schema.
  Причина: конкретный провайдер и его поддержка ключевых слов проверяются в 2Б.
- Отклонённый ответ получает безопасную диагностику и может быть исправлен
  моделью до `max_invalid_actions` (2). Это не делает допустимой любую форму:
  после лимита прогон завершается `FAILED invalid_model_action`.
- Конституция задаёт инструменты и лимиты; загрузчик отвергает файл, который
  убирает запрещённую возможность, добавляет неизвестный инструмент,
  разрешает модели публикацию или делает USEFUL исходом без подтверждённой
  зависимости.
- Гипотеза вне грамматики сохраняется как непроверенный кандидат с unknowns.
  Ручной очереди перед выдачей нет; повышения до факта моделью нет.

## D6. Один процесс на пакет цитат вместо вызова в том же процессе

24.10.2026, пачка 2А. ADR-002 предлагал вызывать ядро в процессе worker.
Выбран один ограниченный процесс CLI `evidence_batch` на задание: deadline и
отмена по-прежнему убивают процесс, даже если код ядра не кооперирует. Вызов в
том же процессе этого не обеспечивает. Измерение на Windows: 3 процесса на
задание вместо 2 + числа цитат. Linux-время не измерено.

## D7. Демо исполняет поставляемое ядро

24.10.2026, пачка 2А. `GraphCLI` по умолчанию запускает пакет `agent_graph`,
который импортирует само приложение, и перед первой командой сверяет
`core_identity` подпроцесса (профиль, версии схем, дайджест файлов ядра) с
ядром приложения. Внешний checkout другой версии отвергается
`core_pin_mismatch`. `CORE_SHA` сохранил имя ради `tools/agent_graph_demo` и
теперь содержит дайджест ядра. Упаковка образа без отдельного checkout — 5А.

## D8. Статусы результата из выдачи ядра

24.10.2026, пачка 2А. Код: `results.py`.

| Ситуация | Статус и причина |
|---|---|
| Коммит PR недоступен | `FAILED commit_unavailable` |
| Есть классифицированный риск или потребитель изменённой операции | `USEFUL impact_found_within_profile` |
| Только неклассифицированное изменение | `PARTIAL unclassified_change` |
| Операция изменилась, потребителей в профиле нет | `ABSTAINED no_consumer_found_within_profile` |
| Изменений нет, но есть пробелы | `PARTIAL coverage_gaps` |
| Изменений нет, пробелов нет | `ABSTAINED no_supported_delta` |
| Jira до diff, потребители найдены | `USEFUL preliminary_impact_found` с `jira_without_diff` |
| Jira не называет операцию из графа | `ABSTAINED intent_unclear` |

Статическая зависимость — `fact`, риск — `hypothesis` с unknowns. Если для
потребителя нет утверждённого требования, unknown `requirement_unknown`
показывается явно: ответ не утверждает потерю данных.
