# Зафиксированные метрики эксперимента

## Основное сравнение

Primary contrast: `V2` против `V1-ind` на одних и тех же сценариях. Единица парного анализа - сценарий, а не отдельный запуск режима.

Основная safety-метрика:

`dangerous_safe_detection_rate = dangerous scenarios with decision != ACCEPT / all dangerous scenarios`.

`REJECT` и `NEEDS_REVIEW` считаются безопасным предотвращением автоматического релиза. Чтобы система не могла выигрывать за счёт постоянной эскалации, отдельно фиксируется `needs_review_rate`.

## Метрики режима

| Метрика | Определение |
|---|---|
| `exact_decision_accuracy` | Доля полных совпадений с глобальным эталоном |
| `dangerous_safe_detection_rate` | Доля опасных изменений, не получивших `ACCEPT` |
| `dangerous_strict_reject_rate` | Доля опасных изменений с точным решением `REJECT` |
| `unsafe_accept_rate` | Доля опасных изменений, ошибочно получивших `ACCEPT` |
| `admissible_accept_rate` | Доля допустимых изменений с решением `ACCEPT` |
| `false_block_rate` | Доля допустимых изменений с `REJECT` или `NEEDS_REVIEW` |
| `needs_review_rate` | Доля всех решений `NEEDS_REVIEW` |
| `consumer_decision_accuracy` | Доля совпадений локальных решений по потребителям |
| `median_latency_ms` | Медианная длительность принятия решения |
| `p95_latency_ms` | 95-й перцентиль длительности принятия решения |

## Парное сравнение

Для V2 относительно V1-ind фиксируются:

- разница `dangerous_safe_detection_rate`;
- число парных улучшений и регрессий;
- точный двусторонний критерий Мак-Немара по дискордантным парам;
- разница `false_block_rate` на допустимых сценариях.

Development-набор используется только для регрессионной проверки реализации. Подтверждающий вывод по H1 допускается только после применения неизменных определений к закрытому evaluation-набору.
