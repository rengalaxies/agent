# Сопроводительное письмо

Черновик к отправке после встречи. Перед отправкой заполнить поля в
квадратных скобках и приложить `pilot-presentation.pdf`. Письмо и
презентацию отправляет человек из нашей команды; автоматически они никуда
не уходят.

---

**Тема:** Пилот: проверяемый список потребителей для изменений вашего API

[Имя], добрый день.

Спасибо за время на встрече [дата]. Коротко повторю, что мы предлагаем.

Когда ваша команда меняет внутренний API, кто-то должен ответить, кого это
заденет у потребителей в других репозиториях. Мы предлагаем проверить на
ваших реальных изменениях, помогает ли в этом наш инструмент вместе с нашим
инженером. По каждому изменению за время пилота вы получите список мест
вызова у потребителей со ссылкой на строку в коммите, перечень того, что
проверить, и явный список мест, которые инструмент не разобрал.

Что важно знать заранее:

- Инструмент сегодня распознаёт узкий случай: потребители на Python
  вызывают API через `requests`, API объявлен в FastAPI или OpenAPI JSON.
  На клиентском коде он ещё не запускался, поэтому первым шагом идёт проба
  покрытия на вашем коде.
- Пилот рассчитан на 12 изменений за 6 недель. Мы сравниваем три способа
  поиска на одних задачах: ваш текущий процесс, ваш coding agent без нашего
  модуля и агент с модулем. Эталон вслепую собирает ваш сотрудник.
- Критерии решения записаны заранее. Если модуль пропустит больше серьёзных
  потребителей, чем ваш агент без него, мы прямо скажем, что инструмент вам
  не нужен.
- От вашей команды нужно около 12-16 часов на 2-3 человек за 6 недель (это
  оценка до замера) и доступ на чтение. Код не покидает ваш контур, ИИ-модель
  не используется. Пилот бесплатный.
- Экономию мы не обещаем: её и измеряет пилот. При любом исходе у вас
  останутся отчёты по вашим изменениям и измеренная доля потребителей,
  которых ваш coding agent пропускает на вашем коде.

Чтобы начать, предлагаю согласовать:

1. API для пилота: [название API].
2. Владельца с вашей стороны: [имя техлида] и того, кто согласует доступ:
   [имя].
3. Материалы для пробы покрытия: доступ на чтение к репозиториям API и
   потребителей, адреса сервиса по окружениям, список изменений API за
   последние 6 месяцев, CODEOWNERS, машина с Linux или WSL2 в вашем контуре.
4. Следующую встречу: [дата и время]. На ней разберём ваше последнее
   изменение API и запустим пробу покрытия.

После пробы мы скажем, применим ли инструмент к вашему коду. Если нет,
пилот не начинаем и объясняем почему.

Презентация во вложении. Методика, ограничения и источники всех цифр
собраны в её приложении.

[Подпись]
