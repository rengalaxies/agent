# Пачки до автономного MVP

24.10.2026. Это задачи разработки. Постоянного штата сопровождения у клиента
не предполагается. Сроки прежнего ручного пилота не являются оценкой нового MVP.

## 1. Решения и достоверное предложение

#45/#46 слиты. Уточнить #44/#48, согласовать эти документы и восемь слайдов
#49, связать решения с задачами. Без новых ВМ и платных серий. Результат —
единый план с честной границей «есть / предстоит».

## 2. Проверяемые интерфейсы и модельный цикл

- Выходные контракты ядра, неизвестные коды и версии профиля.
- Вход по base/head Git и закреплённым версиям потребителей; общий сигнал
  неклассифицированного изменения операции. Изменения вспомогательных
  функций вне отслеживаемых оснований остаются явным ограничением.
- Разделение шума и реальных пробелов без объявления неразобранного кода
  полным покрытием.
- Безопасная диагностика отклонённого action; согласование schema/executor
  офлайн; затем отдельная квалификация фиксированной открытой модели.
- Конституция ограничивает инструменты, параметры, статусы и бюджеты.

Приёмка: одинаковые SHA воспроизводят фактический результат; поддельные
основания и запрещённые действия отвергаются; полезный успех, частичный
ответ и отказ различимы; завершён отрицательный контроль. До квалификации
модельный контур не объявляется автономным. Старая серия неизменна.

## 3. Обновляемый граф и источники

- Идентичность сервисов/операций, версии манифестов, основания и история.
- Корректная свежесть и память; инкрементальность по замерам со сверкой
  полного пересчёта. Несвязанная правка не обесценивает все решения.
- Один runtime-коннектор по доступному контуру: Tempo/OTel либо access logs.
- Код, наблюдение и кандидат модели раздельны; конфликты, удаление связей,
  область видимости, простой просмотр/запросы человека.

Приёмка: изменение обновляет затронутые связи; отказ источника показывает
устаревание; отсутствие трафика не удаляет зависимость; расширение области
не скрывает доступную историю и не раскрывает чужие данные.

## 4. Jira и PR без оператора

- События выбранного Jira-проекта и Git-хостинга, общий анализ и граф.
- Jira: вероятная область влияния по тексту; PR: уточнение по diff/версиям.
- Очередь, дедупликация, ограниченные повторы, восстановление после рестарта,
  отмена устаревшего задания при новом head.
- Одно обновляемое сообщение с основаниями; отдельное право публикации;
  отсутствие запуска от собственного комментария. Неясная задача даёт
  вопросы в результате, а не бесконечное ожидание ручного уточнения.

Приёмка: событие автоматически даёт один актуальный результат; пользователь
не запускает анализ вручную; старый head не публикуется как текущий; сбой
внешней системы не теряет очередь.

## 5. Установка и эксплуатация из коробки

- Закреплённый образ/релиз на Linux-ВМ, конфигурация источников, модели,
  секретов и конституции; healthcheck, начальный граф, пробное событие.
- План ресурсов и Cloud.ru-адаптер в разрешённой области и бюджете;
  модель не выбирает произвольные shell-команды.
- Диагностика, восстановление временных отказов, обновление, резервная
  копия и проверенный возврат.

Приёмка: чистая установка и сквозной smoke; повторный запуск без дубликатов;
понятная ошибка доступа; обновление/возврат сохраняют историю; фактический
установленный релиз даёт результат после пробного события.

## 6. Готовность и полезность

Отложенная серия задач/PR с независимо известными последствиями, сравнение
с обычным агентом при одинаковых доступах, замер установки и ручных минут.
Критерии фиксируются до прогона. Проверяются качество, своевременность,
стоимость, полезные действия и работа без ручного управления. Отказы
считаются отдельно. Затем контролируемое подключение реальной команды
без постоянного инженера.
