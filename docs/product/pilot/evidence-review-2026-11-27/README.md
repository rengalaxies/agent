# Проверка разбора доказательств ImpactMap

Я сохранил вторичный анализ E3/E6 отдельно от исходных результатов. Новых запусков продукта и независимых случаев в этой работе нет.

- [Разбор ошибок, порогов и пяти решений](../EVIDENCE-ANALYSIS-2026-11-27.md).
- [Пять проверяемых случаев](../WORKED-CASES-2026-11-27.md).
- [50 строк по случаям](case-analysis.csv), [чувствительность порогов](threshold-sensitivity.csv).
- [Машинная сводка](analysis.json), [входы и хеши пяти примеров](worked-cases.json).
- [Переносимая проверка](verify.py), только стандартная библиотека Python 3.

## Источники

E3: неизменяемый [снимок E2](https://github.com/rengalaxies/agent/tree/f50cdf255c5da36fcfc5882ffb1638c1348e190c/research/evaluation/development-2026-11-15). E6: [сохранённая серия](../e6-2026-11-27/README.md). Версии отличаются: E3 — профиль http-requests-7, E6 — http-requests-9; числа не объединяются в независимую оценку.

## Воспроизведение проверки

Получить снимок E2 и текущую документацию main в две отдельные папки. Выполнить из каталога с этими файлами:

```sh
python3 verify.py --e3 /path/to/e2/research/evaluation/development-2026-11-15 --e6 /path/to/main/docs/product/pilot/e6-2026-11-27 --analysis .
```

Проверяются исходные хеши сводок и плана, 80 опубликованных normalized E3, 20 raw и normalized E6 по receipts, 50 строк разбора, пять примеров и 19 строк чувствительности. Проверка не запускает продукт и не перезаписывает исходники или результаты.

Публичный комплект E6 содержит raw.json, payload и normalized. Я проверил все 20 raw и normalized по receipts также в копии, извлечённой из текущего Git-дерева. verify.py сообщает количество доступных raw; для неполной копии число меньше 20 означает неполную проверку raw. В AUD-0010 снимки provider в результате пусты (WORKTREE, commit=null): это зафиксированная ошибка доступа; SHA в worked-cases.json описывают сохранённый вход корпуса.

## Как интерпретировать

LS1 выдаёт буквального кандидата. FP означает лишнего кандидата по принятому эталону влияния, а не утверждение baseline о сломанном сервисе. Четыре ответа E7 и их оценки этим разбором не изменены. Пороги H1 сохранены; sensitivity показывает их целочисленные последствия, а не оптимальность для клиента.
