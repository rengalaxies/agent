# Установка из коробки

Цель — повторяемое подключение без постоянного инженера. Это требования,
которые ещё предстоит реализовать и проверить на автономном сервисе.

## Одна поставка, два пути

1. Закреплённый релиз на предоставленной Linux-ВМ.
2. Cloud.ru-адаптер создаёт ВМ в разрешённом проекте/бюджете и запускает
   ту же установку. Доступ к облаку нужен для проверки этого пути,
   не для документов пачки 1.

Модель может работать на отдельном endpoint; GPU на ВМ сервиса не обязателен.
Маршрут контекста явно задаётся клиентом.

Параметры → план ресурсов → разрешённое применение → релиз по digest →
источники/модель/конституция → healthcheck → пробное чтение → граф → пробное
событие Jira/PR → отчёт готовности.

Повторный запуск сверяет состояние, не создаёт дубликаты. Обновление
сохраняет историю и проверенный возврат. Отказ источника — ограниченные
повторы и видимая область устаревания. Первичные доступы и рамки платных
ресурсов задаются владельцем контура; обычные действия внутри них не
требуют подтверждения каждого шага.

В репозитории есть hash-locked сборка демо, installer, остановка/возврат,
Terraform и Cloud.ru workflow. Часть относится к прежнему продукту и
закрепляет старые SHA/проекты; это не универсальная готовая коробка.

Приёмка: чистая и повторная установка, понятный отказ неверного доступа,
обновление/возврат с историей, восстановление очереди и результат пробного
события. Качество анализа проверяется отдельно от здоровья установки.
