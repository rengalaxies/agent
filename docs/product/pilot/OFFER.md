# Закрытый пилот: влияние изменения HTTP API на соседние команды

Редакция 29.10.2026. Предыдущая редакция от 24.10 описывала целевой сервис и есть в
истории Git. Эта редакция описывает то, что поставляется сейчас, и условия первого
закрытого технического пилота. Цена, срок и объём ниже: предложение с допущениями,
а не утверждённая сделка.

## Кому и зачем

**Пользователь:** команда, которая владеет внутренним HTTP API на Python и меняет его
через задачи Jira и pull requests на GitHub. Потребители API живут в соседних
репозиториях других команд.

**Проблема.** Автор изменения не всегда знает всех потребителей. Пример из показа:
Orders уменьшает размер страницы `GET /orders` со 100 до 20. Reporting читает одну
страницу без `page_size` и молча теряет записи в отчёте.

**Как это делают сейчас.** Автор ищет вызовы поиском по коду, спрашивает в чате,
полагается на ревьюеров и тесты потребителей. Coding agent может сделать тот же поиск
по запросу, если ему дали доступ к нужным репозиториям и он знает, что спросить.

**Что делает сервис.** После подключения он сам, без запуска человеком, пишет один
комментарий и обновляет его:

| Событие | Что появляется | Сила вывода |
|---|---|---|
| Создана задача Jira с упоминанием операции | Возможные потребители, место вызова на закреплённом коммите, что проверить до начала работы | Предварительный: кода ещё нет, это не доказательство поломки |
| Открыт или обновлён PR | Изменённая операция, затронутые потребители, путь и основания `репо@коммит:файл#строки`, что проверить | По diff двух коммитов в пределах профиля; тесты не запускаются |
| В PR исправили изменение | Тот же комментарий: какая находка исчезла и с какого поколения | Отсутствие находки в профиле, не выполненная проверка |
| Изменение вне профиля | Воздержание с причиной | Сервис не утверждает отсутствие влияния |

**Решение, которому он помогает:** кого из потребителей позвать в review и что
проверить до merge, а для задачи: кого предупредить до начала работы.

## Что поставляется (уровни доказательства)

| Что | Уровень | Где проверено |
|---|---|---|
| Анализ HTTP/Python: FastAPI-маршруты, вызовы `requests`, изменение page_size и удаление операции | LOCAL, CI | авторские наборы и регрессии; [M4-A](https://github.com/rengalaxies/agent/pull/72) сужает положительные доказательства |
| Webhook Jira и GitHub, очередь, один комментарий, дубли, новый head, сбой API, собственный комментарий | LOCAL, CI | [M2](../../implementation/autonomous-mvp/m2-2026-10-28/README.md), 9/9 локального сценария |
| Понятный переход после исправления и показ | LOCAL | [R2](https://github.com/rengalaxies/agent/pull/75) |
| Обновление старых комментариев после смены профиля | LOCAL | [#76](https://github.com/rengalaxies/agent/pull/76) |
| Релиз, установка, обновление, откат с systemd | CI | релиз `agent-service-0.1.0-g14e65e8affe3`, run 40693796501 |
| Две private pilot-репозитории, App ID и bot ID | REAL_API | [M2-A](../../implementation/autonomous-mvp/m2-a-2026-10-28/README.md) |
| Аутентификация сервисной GitHub App | NOT_RUN | ждёт PEM в защищённом environment ([#74](https://github.com/rengalaxies/agent/pull/74)) |
| Настоящие webhook, комментарии App, Jira | NOT_RUN | нужны установка M3, HTTPS и Jira |
| Установка на ВМ Cloud.ru | BLOCKED | хост остановлен, разбор у поддержки ([#71](https://github.com/rengalaxies/agent/pull/71)) |
| Польза для команды, незнакомый проект | UNVERIFIED | нет участника и независимых случаев |
| Модель | OFF | допуск не пройден, анализ детерминированный |

Чего не обещаем: другие языки и протоколы (PostgreSQL, RabbitMQ, gRPC из раннего
видения), полноту поиска потребителей, доказательство совместимости, запуск тестов,
экономию времени и преимущество над coding agent. Отсутствие найденного потребителя не
доказывает его отсутствия.

## Входные требования

- Один HTTP API на Python (FastAPI) и его потребители на Python с `requests`.
- 2–5 репозиториев GitHub в одной организации. Проект Jira по желанию; без него
  работает только путь PR.
- Linux-ВМ для сервиса с HTTPS-адресом для двух webhook. Ресурсы установки ещё не
  измерены на целевом хосте.
- Отдельная GitHub App в организации участника с правами Metadata/Contents/Pull
  requests read и Issues write на выбранные репозитории. Для Jira нужен отдельный
  технический аккаунт с правом комментировать в одном проекте.
- Разрешение владельца данных на обработку кода и текстов задач на этой ВМ.
  Данные не уходят во внешнюю модель: модель выключена.

Порядок подключения, выход и инциденты описаны в [CONNECT.md](CONNECT.md).

## Предложение по пилоту (допущения, требует решения владельца)

- **Длительность:** 4 недели после первого настоящего комментария. Допущение: этого
  хватит на 10–20 изменений API у одной команды.
- **Объём:** один API, 2–5 репозиториев, одна команда-автор и одна-две команды-потребители.
- **Участие людей:** час на подключение со стороны администратора GitHub/Jira, затем
  добровольная оценка комментариев. Минуты замеряются, а не оцениваются задним числом.
- **Цена:** не назначена. Варианты для решения владельца: бесплатный пилот за
  измеренную обратную связь или фиксированная плата за установку. Экономики
  эксплуатации пока нет.
- **Результат пилота:** отчёт по [протоколу](PROTOCOL.md#протокол-закрытого-пилота-29102026)
  с числами: найденные и пропущенные влияния, ложные сигналы, воздержания, время до
  комментария, человеческие минуты. Положительный результат не гарантируется.

## Что нужно до приглашения первого участника

Технический пилот готов, когда выбран и проверен релиз, работает настоящий внешний
контур, путь пользователя понятен и согласованы условия доступа, остановки и оценки.
Доказанная польза является результатом пилота, а не условие приглашения. Текущий список
оставшихся условий лежит в [индексе 29.10](../../implementation/autonomous-mvp/pilot-2026-10-29/README.md).
