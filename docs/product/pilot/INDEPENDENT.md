# Независимая проверка: что нужно от участника

29.10.2026. **Статус: подготовлено, не выполнено.** Независимых случаев пока нет.
Авторские Orders/Reporting, 25 методов M4-A и наборы 6-r1..6-r3 написал исполнитель
реализации. Они проверяют регрессии и не измеряют качество на незнакомом проекте.
Новый авторский набор здесь не создаётся и независимым не называется.

## Что запросить у swan-Dive или инженера незнакомого проекта

| Данные | Формат | Зачем |
|---|---|---|
| Репозитории | 2–5 repo с HTTP API на Python и его потребителями, доступ на чтение | Источники для сервиса и агента |
| Изменения | 5–15 изменений API: прошлые PR (base и head SHA) или задачи Jira с текстом | Входы сравнения |
| Эталон | Для каждого изменения: какие потребители затронуты, насколько серьёзно, что им надо проверить. Пишется до просмотра ответов | Пропуски и ложные сигналы |
| Отрицательные случаи | 2–3 изменения без влияния на потребителей | Проверка ложных сигналов |
| Разрешение | Право обрабатывать код на машине проверки, без внешней модели | Юридическая граница |

Шаблон заполнения: [independent-cases.template.json](independent-cases.template.json).
Эталон хранится отдельно от входов, у участника или в закрытом файле, и не
передаётся анализатору.

## Как прогоняем

1. Участник присылает входы. Исполнитель фиксирует версию сервиса (commit, profile),
   версию агента и лимиты, публикует manifest входов **до** получения эталона.
2. Сервис и baseline-агент прогоняются на тех же репозиториях и SHA. Используется
   существующий runner `tools/autonomous_mvp/readiness`: свежий state на каждое
   изменение, oracle не читается. Нужен адаптер «внешний мир»: repo по пути и SHA
   вместо сгенерированного мира. **Адаптер ещё не написан**: это следующий код после
   получения первых данных, формат входов задаёт шаблон.
3. Ответы замораживаются (hash в manifest), затем участник присылает эталон.
4. Оценку делает участник или третий инженер по эталону. Исполнитель не правит
   анализатор под эту выборку. Если правка нужна, она проверяется на новой выборке.

## Если участника нет

Можно взять открытый проект на фиксированном SHA с совместимой лицензией: FastAPI-сервис
и его Python-клиенты в одной организации. Ограничение: эталон тогда пишет исполнитель
реализации, и результат помечается «автор участвовал в ожиданиях». Это лучше
синтетики, но не заменяет независимого инженера. Выбор проекта и SHA не сделан.

## Чего не делаем

Не возобновляем закрытые модельные серии, не включаем модель, не используем
проверочную выборку для подгонки, не переписываем 2b-r1 и 6-r1..6-r3.
