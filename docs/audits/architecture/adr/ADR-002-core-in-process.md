# ADR-002. Ядро работает внутри процесса приложения; CLI остаётся тонкой обёрткой

Статус: предложено аудитом 22.10.2026.

## Контекст

Worker демо вызывает ядро через `subprocess` на каждую операцию и на каждую
уникальную цитату (`worker.py`, `graph_cli.py`). На демо-сценарии это 11-12
процессов `evidence` на job. На синтетическом корпусе из 20 файлов job анализа
даёт 491 цитату; при 0,47 с на процесс расчёт даёт около 231 с против
лимита 180 с (`DemoSettings.job_seconds`). Это экстраполяция по 20 измеренным
вызовам на Windows, а не полный прогон job на целевой Linux-среде. Каждый процесс заново импортирует
pydantic, открывает SQLite и разбирает JSON всего контекста.

Процесс CLI выбирался как граница безопасности: фиксированные аргументы,
нет shell, отдельное окружение. Вызов функции в том же процессе сохраняет
запрет исполнения анализируемого кода и сетевых запросов, но не эквивалентен
изоляции процесса: общими становятся память, последствия сбоя и механизм
остановки. Перед принятием ADR нужно проверить отмену, deadline и ресурсные
пределы. Пакетная CLI-команда остаётся допустимой альтернативой, если отдельный
процесс нужен для этих границ.

## Решение

1. Worker импортирует `agent_graph` и вызывает `Graph` напрямую, один объект на
   job. Проверка цитат выполняется одним вызовом на пачку (`get_evidence` по
   списку), без отдельного процесса.
2. `python -m agent_graph` остаётся интерфейсом для coding agent и оператора.
   Его выход описывается JSON Schema (ADR-003).
3. Отдельный checkout ядра, `core.lock.json` с хешами файлов и `CORE_SHA` в
   демо заменяются зависимостью от версии пакета (ADR-003).

## Альтернативы

- Оставить CLI и добавить пакетную команду `evidence`. Убирает фан-аут
  (одна сотня процессов становится одним), но оставляет 0,5 с на каждую из 2-3
  операций job и двойную сериализацию. Приемлемо как промежуточный шаг.
- Долгоживущий процесс ядра с RPC. Добавляет протокол и жизненный цикл без
  выигрыша над вызовом функции.

## Последствия

- Время job демо определяется работой ядра, а не числом цитат.
- Ошибки ядра получают traceback в серверном журнале (ADR-008);
  наружу по-прежнему уходит только стабильный код.
- Ядро и демо меняются вместе одной версией; отпадает перезакрепление из
  8 файлов и требование merge commit.

## Как проверить

Время job `analyze_change` на демо-сценарии и на синтетическом корпусе из
100 файлов; число запущенных процессов на job равно 0. Цель: job на 100 файлах
укладывается в 10 с.
