# ADR-004. Источник истины это коммит Git, анализ принимает пару коммитов

Статус: предложено аудитом 22.10.2026.

## Контекст

Ядро читает то, что оператор положил в каталог, и называет это версией по
строке `revision` из policy, которую не проверяет. Доверять можно только
утверждению "эти байты лежали в этом каталоге": SHA-256 каждого файла и точная
цитата повторно сверяются при чтении. Связи с веткой, коммитом и удалённым
репозиторием нет. `analyze_change` сравнивает сохранённый контекст с текущим
содержимым диска, поэтому проанализировать PR можно, только подменив файлы.

В демо исходники генерируются строковыми заменами (`scenarios.py`), так что
вопрос получения реального кода демо не решало.

## Решение

1. Репозиторий в policy задаётся URL внутреннего Git и веткой, а не каталогом.
   Ядро держит bare-зеркало (`git fetch`) и читает файлы коммита через
   `git archive` или `git cat-file`, не через рабочее дерево.
2. `revision` это SHA коммита. `source_id` строится из SHA blob-а Git, который
   уже адресует содержимое; отдельный обход с SHA-256 не нужен.
3. `analyze_change(base, head)` принимает пары коммитов по каждому
   затронутому репозиторию. Список изменённых файлов берётся из
   `git diff --name-only base head`; остальные файлы берутся из кеша
   (ADR-005).
4. Каталог на диске остаётся режимом для локальной работы разработчика, с
   пометкой `revision=WORKTREE` и без претензии на воспроизводимость.

## Почему этому можно доверять

SHA коммита проверяем любым участником с доступом к репозиторию. Ревьюер PR
может воспроизвести вывод, сославшись на два SHA. Подмена файлов на диске
перестаёт влиять на результат.

## Альтернативы

- Оставить каталоги и добавить `revision` как обязательный SHA без проверки.
  Ничего не меняет в доверии.
- Читать через API хостинга (GitLab/GitHub). Требует сетевого доступа и токена
  на каждый запрос; в закрытом контуре зеркало проще и не зависит от лимитов API.

## Последствия

- В поставку добавляется `git` (есть в любом базовом образе) и каталог
  зеркал. Новых сервисов нет.
- Доступ к репозиториям даётся read-only ключом развёртывания; это граница
  полномочий, которую v4 требовал задать до сбора.
- Синтетический сценарий демо превращается в тестовый репозиторий с
  коммитами A, B, D, E.

## Как проверить

`analyze_change` на настоящем PR внутреннего сервиса по двум SHA без доступа
к рабочему дереву; повторный запуск через неделю даёт тот же результат.
