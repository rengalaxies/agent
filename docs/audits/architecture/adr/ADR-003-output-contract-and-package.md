# ADR-003. Описанный контракт выдачи и ядро как версия пакета

Статус: предложено аудитом 22.10.2026.

## Контекст

- `schemas/agent-graph-1.json` описывает только входы. Формат контекста,
  зависимостей и анализа существует только в коде. Worker ищет цитаты по набору
  ключей в любом месте JSON, UI сопоставляет коды `usage` и `findings[].code`.
  Новый код находки ядра (`OPERATION_REMOVED`) UI показывал как "требуется
  повторная проверка", и ни одна проверка этого не заметила.
- Демо закрепляет ядро отдельным checkout другого SHA того же репозитория и
  сверяет SHA-256 каждого файла с `core.lock.json`. Тесты демо по умолчанию
  берут ядро из того же репозитория. Любая правка ядра требует второго коммита,
  который меняет 8 файлов вне ядра (lock, `CORE_SHA`, `PROFILE`, два workflow,
  delivery, RUNBOOK, README), и merge commit, чтобы SHA сохранился.
- Один `pyproject.toml` упаковывает исследовательский протокол ВКР,
  `change_completion`, ядро и демо; демо ставится из отдельного lock-файла.

Такое закрепление появилось, когда ядро и демо делали разные исполнители
("пачка 1" и "пачка 2"). Для одной небольшой команды это налог на каждую правку.

## Решение

1. Описать JSON Schema выдачи: `context`, `dependencies`, `analysis`,
   `evidence`, с перечислением кодов `usage`, `findings[].code`, `deltas[].code`
   и `gaps[].code`. Ядро проверяет свою выдачу в тестах; демо проверяет входящие
   данные при чтении и показывает неизвестный код как неизвестный.
2. Выделить ядро в пакет `agent-graph` со своим `pyproject.toml` (каталог
   `src/agent_graph` можно оставить на месте). Версия пакета включает `PROFILE`.
   Демо зависит от точной версии колеса в своём lock-файле с хешем.
3. Убрать `core.lock.json`, `CORE_SHA` и отдельный checkout. Целостность
   ядра в образе обеспечивает хеш колеса в lock-файле, как у остальных зависимостей.

## Альтернативы

- Оставить как есть: каждая правка ядра это два коммита и 8 сопутствующих
  файлов; ошибка в любом из них ломает CI демо.
- Перенести код ядра внутрь демо. Убирает закрепление, но смешивает ядро для
  coding agent с веб-приложением.

## Последствия

- Правка ядра становится одним PR, squash merge допустим.
- Изменение выдачи без обновления схемы ломает тест ядра, а не показ.
- Исследовательский код и продукт перестают делить один пакет.

## Как проверить

Число файлов вне `src/agent_graph` и тестов, которые меняются при правке
семантики ядра: сейчас 8, цель 1 (lock-файл демо). Тест, который подаёт в UI
выдачу с неизвестным кодом находки и ожидает текст "неизвестно".
