# Согласование автономного сервиса — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Завершить пачку 1: согласовать PR #44/#47/#48/#49 с автономным B2B-сервисом и выпустить короткие PPTX/PDF.

**Architecture:** Документы описывают один целевой сервис, а реализованное отделяют от плана. Jira и PR используют общий граф и автоматическую обработку. Эта пачка не реализует новый сервис.

**Tech Stack:** Markdown, GitHub Git API, JavaScript ES modules и Artifact Tool для PPTX; экспорт PDF из того же содержимого.

**Spec:** `2026-10-24-autonomous-service-design.md` рядом с этим планом; затем копия в `docs/superpowers/specs/` ветки #47.

## Global Constraints

- Никакого постоянного оператора агента, инженера сопровождения или разметчика в продуктовой выдаче.
- Основной рассказ — восемь слайдов, с объяснением графа и честным сравнением конкурентов.
- Модель и конституции не объявляются квалифицированными без проверки; данные компании не выдаются за доступные заранее.
- Прежняя серия и критерий 20% сохраняются как история; не меняются задним числом.
- Новые ресурсы Cloud.ru и платные вызовы моделей не входят в пачку 1.

## Review Focus

- Устаревший текст о ручном сопровождении может остаться в предложении или письме — проверить все действующие документы и текст слайдов.
- Маркетинговые утверждения о графе могут опережать код — сверить таблицу «сейчас / план» с аудитом и серией.
- Изменение базы #49 после #47 может потерять документы — обновлять ветку без force и сверять ancestry.
- Экспорт PPTX и PDF может расходиться — общий текст, восемь страниц, визуальная проверка каждого слайда.
- Сохранённые старые материалы могут выглядеть действующими — явная отметка архива и ссылки на закреплённый исходный срез.
