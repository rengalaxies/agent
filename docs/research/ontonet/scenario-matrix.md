# Матрица сценариев

24.10.2026. Сравниваются процессы, а не совпадающие слова. Для каждого
сценария указано покрытие у Ontonet, у нас и у ближайших альтернатив клиента.

Оценки покрытия:

- **ПОЛНОЕ** - сценарий выполняется без ручной подмены ключевого шага;
- **ЧАСТИЧНОЕ** - выполняется часть, либо ключевой шаг делает человек;
- **НЕТ** - механизма нет в коде (для нас) или есть явное указание вендора,
  что это делается вручную;
- **НЕИЗВЕСТНО** - в публичных материалах нет сведений. Это не равно "нет".

Для нас дополнительно: **код** (текущая реализация), **синтетика** (работает
только на нашем корпусе), **план**.

Источники Ontonet `[S#]` и страницы PDF см. в [sources.md](sources.md), наши
файлы указаны путями репозитория на `8f010cf`.

## 1. Оценить последствия изменения API

| | Покрытие | Основание |
|---|---|---|
| Ontonet | ЧАСТИЧНОЕ. Если сервисы, операции и потребители уже смоделированы вручную, агент через MCP может обойти связи (`search_entities_by_relations`, `get_entity(related_entities=True)`). Сравнения версий API, разбора diff и алгоритма анализа влияния нет в материалах | [S15]; общий тезис о понимании влияния изменений [S1, S2] МАРКЕТИНГ; пример статьи 07.05.2026, где объекты API заводит агент-аналитик в диалоге [S33]. В PDF анализ влияния назван задачей прикладного контура поверх Onto (с. 8, 11) |
| Мы | ЧАСТИЧНОЕ. `analyze_change` сравнивает base/head и даёт `OPERATION_REMOVED`, `PAGE_DEFAULT_CHANGED`, `PAGE_DEFAULT_UNRESOLVED`, для одиночного запроса `POSSIBLE_TRUNCATION`. Схема ответа, типы, обязательные поля, коды статусов не анализируются. Работает на нашем корпусе из четырёх корней. Реальный клиентский код не проверялся | `src/agent_graph/engine.py:157-225`; `docs/agent-graph-demo/ACCEPTANCE.md` |
| Альтернативы | Coding agent с доступом к репозиториям находит и читает вызовы в любом стеке, но вывод не воспроизводим и не сохраняется между задачами. Инструменты сравнения OpenAPI ловят ломающие изменения спецификации, но не знают потребителей. Consumer-driven contract tests (Pact и аналоги) покрывают только тех потребителей, кто написал контракт | Общеизвестные свойства инструментов, в этом раунде не перепроверялись |
| Неопределённость | Насколько часто у клиентов ломаются потребители именно из-за изменений, не видимых в схеме (поведение, пагинация, default). Не измерено ни у нас, ни у кого-либо в найденных материалах | `docs/product-focus-2026-10-20.md` §8 |

## 2. Найти потребителя в нескольких репозиториях

| | Покрытие | Основание |
|---|---|---|
| Ontonet | НЕТ. Импорта исходного кода и Git нет; связи создаёт и поддерживает человек или агент вручную. Упоминание бота на ревью PR (пост 31.07.2025) иллюстративное, без реализации | [S15, S17]; [S29/324, S29/508]; [S34] |
| Мы | ЧАСТИЧНОЕ. Обнаружение без готовых рёбер в нескольких корнях: AST, профиль `http-requests-3` (литеральные вызовы `requests`), FastAPI и OpenAPI JSON у провайдера, decoy с тем же путём не создаёт ребро. Wrappers, Session, сгенерированные SDK, другие языки дают пробел. Только локальные снимки, подключения к Git-хостингу нет. Реальная модель нашла связь в 2 из 6 сочетаний, контроль с decoy не прошла ни одна | `examples/agent_graph/README.md`; `experiments/evidence_refs_v2/runs/2026-10-22-batch1/README.md` |
| Альтернативы | Поиск по коду по всей организации находит строку пути или hostname в любом языке за секунды, без семантики. Coding agent дополняет поиск чтением кода. Ручная карта сервисов (каталог, wiki) знает только объявленные зависимости | Общеизвестно, не перепроверялось |
| Неопределённость | Доля реальных вызовов, которая попадает в наш профиль. Для типичного корпоративного Python с обёрткой над HTTP-клиентом она может быть близка к нулю. Не измерено | `docs/useful-graph-open-questions-2026-10-21.md` G-03 |

## 3. Объяснить вывод проверяемыми основаниями

| | Покрытие | Основание |
|---|---|---|
| Ontonet | ЧАСТИЧНОЕ. Метод TCM и курс строят цепочку Source → Evidence → Claim собственными шаблонами пользователя. Встроенного типа "свидетельство" со ссылкой на фрагмент нет; "provenance" в MCP означает связь копии с оригиналом. PDF сам отмечает, что связь "поддерживает" в Onto только заявляет основание, а проверить её должны алгоритм и человек | [S7, S15, S29/503]; PDF с. 8 |
| Мы | ПОЛНОЕ в пределах профиля. Каждое ребро имеет repository/revision/path/digest и диапазон строк; `evidence` возвращает проверенный фрагмент; `evidence-refs-v2` связывает предложение модели только с реально прочитанными фрагментами; отдельный барьер `dependency_sufficiency` отвергает точные, но нерелевантные строки. Статусы статической находки, кандидата модели, исправления человека и внешнего отчёта не смешиваются | `docs/evidence-references-v2.md`; `tests/graph/test_evidence_refs.py` |
| Альтернативы | Coding agent может процитировать файл и строку, но цитату никто не сверяет с байтами и версией; при следующем запуске объяснение другое | Наблюдение по нашим сериям: модели ошибались в цитатах (причина ввода v2), `docs/evidence-references-v2.md` |
| Неопределённость | Ценит ли покупатель проверяемость основания настолько, чтобы платить. Сигнал со стороны рынка есть только от вендоров и методологов (PDF, Onto), не от покупателей | PDF с. 15: готовность платить "не подтверждено" |

## 4. Передать полезный контекст coding agent

| | Покрытие | Основание |
|---|---|---|
| Ontonet | ПОЛНОЕ по транспорту: документированный MCP на 69 инструментов, справочный инструмент с планом вызовов, режим только чтения, видео с DeepSeek и Cherry Studio. Содержание контекста целиком зависит от ручной модели. SaaS недоступен с 11.10.2026 | [S3, S12, S15, S31]; [S29/511] |
| Мы | ЧАСТИЧНОЕ. JSON CLI (`prepare_context`, `dependencies`, `evidence`, `analyze_change`). MCP и HTTP API не реализованы сознательно. Совместимость с конкретным корпоративным агентом не проверена. Польза для агента относительно агента без модуля не измерена: 12-задачная серия не проведена | `src/agent_graph/__main__.py`; `docs/agent-graph-implementation-2026-10-21.md` §2, §6 |
| Альтернативы | Агент сам строит контекст чтением репозиториев; файлы заметок (AGENTS.md и подобные) дают постоянную память без отдельного продукта | Общеизвестно |
| Неопределённость | Главная для нас: даёт ли сохранённый контекст выигрыш сверх агента с теми же доступами и заметками | `docs/product-architecture-roast-2026-10-20.md` §3 |

## 5. Исправить ошибочное знание

| | Покрытие | Основание |
|---|---|---|
| Ontonet | ЧАСТИЧНОЕ. Обычные объекты правит редактор напрямую, история изменений объектов в материалах не найдена. Для артефактов памяти агентов есть жизненный цикл draft → submit → accept → revoke → supersede с проверкой SHA тела. Две роли: владелец и редактор | [S15, S17] |
| Мы | ЧАСТИЧНОЕ. Human correction с `supersedes`, хранится поверх наблюдений парсера и переживает пересборку, при новом basis становится `STALE`; модель исправлять не может. Ограничение: один доверенный пользователь ОС, без ролей и согласования | `examples/agent_graph/README.md`; `docs/agent-graph-demo/ACCEPTANCE.md` |
| Альтернативы | У coding agent исправление живёт в заметках или промпте; нет связи исправления с версией источника | Общеизвестно |
| Неопределённость | Сколько исправлений потребуется на реальном корпусе и сколько стоит их поддержка. Не измерено | G-09 |

## 6. Обновить знания после изменения исходников

| | Покрытие | Основание |
|---|---|---|
| Ontonet | НЕТ как функция: коннекторов с синхронизацией нет, возможна своя автоматизация через n8n или API. "Автоматизация по событиям изменения модели" заявлена для Enterprise, это события внутри модели, а не в источниках (НЕИЗВЕСТНО) | [S13, S16, S29/389] |
| Мы | ЧАСТИЧНОЕ. По запросу полный повторный скан, новые файлы и вызовы обнаруживаются, изменение байтов даёт `STALE`, сбой даёт `UNKNOWN`, смена профиля инвалидирует старый basis. Событий, расписания и инкрементального индекса нет | `examples/agent_graph/README.md`; G-06 |
| Альтернативы | Coding agent каждый раз читает текущий код, поэтому всегда "свежий", но ничего не помнит. Поиск по коду индексирует автоматически | Общеизвестно |
| Неопределённость | Стоимость полного пересчёта на реальном объёме кода не измерена | `docs/agent-graph-implementation-2026-10-21.md` §8 |

## 7. Использовать решение внутри организации

| | Покрытие | Основание |
|---|---|---|
| Ontonet | ЧАСТИЧНОЕ. Заявлены on-prem, частное облако, OEM; запись в реестре российского ПО (по вторичному источнику); две роли; SSO и аудит только в маркетинговой строке. | Альтернативы | Разрешённый в компании coding agent и поиск по коду уже прошли закупку и безопасность | Предположение, у конкретного клиента проверяется |
| Неопределённость | Наличие у целевого клиента разрешённого coding agent с доступом ко всем нужным репозиториям; политика вывоза кода в облачную модель | `docs/useful-graph-open-questions-2026-10-21.md` §1.2 |

## Что следует из матрицы

1. Ontonet и мы почти не пересекаемся по выполняемой работе. Onto хранит
   то, что в него положили люди и агенты. Мы извлекаем факты из кода и
   проверяем их. Общий у нас только принцип: основание отдельно от вывода.
2. Наш реальный конкурент в сценариях 1, 2, 4 и 6 - coding agent с поиском по
   коду, а не Ontonet. Против него у нас преимущество только в сценариях 3 и 5,
   и то в пределах узкого профиля.
3. Сценарий 7 у нас отсутствует полностью, у Onto он частичный и рискованный.
