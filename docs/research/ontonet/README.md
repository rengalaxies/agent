# Ontonet и наш продукт: конкурентная и продуктовая экспертиза

24.10.2026. Срез репозитория `main` = `8f010cf`. Публичные материалы Onto и
IM Center, White Paper "Trust Context" (PDF от владельца проекта). С компаниями
не связывались, аккаунтов не создавали.

## Вывод в пяти строках

1. Ontonet (Онто) - редактор графовой модели с документированным MCP на 69
   инструментов. Модель знаний строят люди и агенты вручную. Код, Git и
   OpenAPI как источник, анализ влияния изменений API в публичных материалах
   отсутствуют. Компания из 3 человек, SaaS не работает с 11.10.2026.
2. White Paper написан Станиславом Карамушко (IM Center) в партнёрстве с Onto.
   Это методология и продвижение курса, а не описание готового продукта. Сам
   документ признаёт спрос неподтверждённым. Его предмет - контекст
   управленческих решений по документам, не изменения кода.
3. Ontonet нам почти не конкурент: мы делаем разную работу. Наш настоящий
   конкурент - coding agent с доступом к репозиториям, который у клиента уже есть.
4. Наше единственное подтверждённое кодом отличие - проверяемость и память:
   основания на уровне байтов, ограниченный отрицательный ответ, вычисляемая
   свежесть. Охват при этом очень узкий: литеральные вызовы `requests`,
   три вида изменений, синтетический корпус, ни одного внешнего пользователя.
5. Рекомендация: **сузить позиционирование** до проверяемых фактов о
   потребителях API для coding agent. Остановить платформенные работы и
   провести сравнение с сильным агентом на реальном случае. Если оно не
   проходит, прекратить продукт. Интеграция с Onto допустима только как
   дешёвый эксперимент.

## Ответы на четыре решения

| Решение | Ответ | Где обоснование |
|---|---|---|
| 1. Может ли клиент решить нашу задачу через Ontonet без нас? | Нет: в Onto нет обнаружения потребителей и анализа diff. Но частично её решает coding agent без Onto и без нас | [assessment.md](assessment.md) §3.1 |
| 2. Может ли наш продукт решить их задачи? | Нет: нет разбора документов, модели полномочий, сроков действия норм, редактора, ролей | §3.2 |
| 3. Есть ли сценарий дополнения? | Технически да: наши проверенные факты о связях в коде как источник для их модели архитектуры через MCP. Коммерчески слабый из-за размера и состояния партнёра | §3.3 |
| 4. Что сохранить, сузить, изменить, прекратить | Сохранить ядро доверия и discovery из кода; сузить позиционирование и стек по реальному случаю; сначала сравнение с агентом, тонкий MCP только для чтения; прекратить RabbitMQ, упаковку модели, облачную обвязку, движение к "графу знаний компании" | §3.4 |

## Ограничения исследования

- Рисунки PDF растровые и не анализировались, учтены подписи и текстовые таблицы.
- Видео Onto оценены по названиям и описаниям, ролики не просматривались.
- Реестр ПО и финансы Onto проверены по вторичным источникам.
- Свойства альтернатив (coding agents, поиск по коду, contract testing) описаны
  по общеизвестным возможностям классов инструментов, без проверки
  документации конкретных продуктов в этом раунде.
- Отсутствие функции в публичных материалах Onto не доказывает её отсутствие в
  продукте. Ключевой вывод об отсутствии загрузки кода опирается на открытый
  код их MCP-сервера, а не только на сайт.
