(`git log`, коммит `02692eb`). За пять недель продуктовая гипотеза менялась

| Дата | Гипотеза | Источник |

## 3. Что реализовано в коде

### 3.1. Ядро `src/agent_graph` (около 1800 строк Python)

CLI `python -m agent_graph` (`src/agent_graph/__main__.py:27`) с командами
`prepare_context`, `dependencies`, `evidence`, `analyze_change`, `propose`,
`report_check`, `investigate`. Состояние в SQLite, одна доверенная учётная
запись ОС.

| Возможность | Что именно работает | Статус |
|---|---|---|
| Обнаружение потребителей без готовой карты | AST-разбор Python. Профиль `http-requests-3`: `requests.get/post/...` и `requests.request` с литеральным URL или конкатенацией с module constant. Провайдер: FastAPI-декораторы верхнеуровневых функций и OpenAPI JSON без `$ref` | РЕАЛИЗОВАНО, но только этот синтаксис (`examples/agent_graph/README.md`) |
| Несколько репозиториев | Политика оператора задаёт несколько корней; в примере четыре: поставщик, два потребителя, decoy | РЕАЛИЗОВАНО на локальных снимках. Подключения к Git-хостингу нет |
| Идентичность сервиса | installation/environment/service/method/path; соответствие адреса сервису задаёт оператор. Совпадение пути `/orders` у двух сервисов не создаёт ребро | РЕАЛИЗОВАНО |
| Анализ diff | Три вида изменений: `OPERATION_REMOVED`, `PAGE_DEFAULT_CHANGED`, `PAGE_DEFAULT_UNRESOLVED` (`src/agent_graph/engine.py:171-181`). Для потребителя с одиночным запросом даёт `POSSIBLE_TRUNCATION` | РЕАЛИЗОВАНО, очень узко. Изменение схемы ответа, типов, обязательных полей, статусов не анализируется |
| Основания | Каждое ребро ссылается на repository/revision/path/digest и диапазон строк; `evidence` возвращает проверенный фрагмент | РЕАЛИЗОВАНО |
| Пробелы и охват | Динамические вызовы, Session, wrappers, kwargs дают явный gap; `COMPLETE_WITHIN_PROFILE` относится только к грамматике | РЕАЛИЗОВАНО |
| Версии и свежесть | Immutable версии контекста, CAS, TTL; изменение bytes или состава файлов даёт `STALE`, сбой сверки даёт `UNKNOWN` | РЕАЛИЗОВАНО |
| Исправление ошибочного знания | Capability `correct`: human correction с `supersedes`, хранится overlay, после нового basis помечается `STALE`. Модель исправлять не может | РЕАЛИЗОВАНО |
| Предложения модели | `investigate`: ограниченный цикл read/propose/finish; результат только `UNAPPROVED_CANDIDATE`. Протокол `evidence-refs-v2` заменяет цитирование ссылками на прочитанные фрагменты (`docs/evidence-references-v2.md`) | РЕАЛИЗОВАНО |
| Отчёты внешнего агента о тестах | `report_check` сохраняет только `EXTERNAL_REPORTED`, без удостоверения | РЕАЛИЗОВАНО |
| Обновление после изменения исходников | Только по запросу, полный повторный скан корпуса. Инкрементального индекса, событий и расписания нет | РЕАЛИЗОВАНО (по запросу); фон - ПЛАН |
| Доступ coding agent | Subprocess CLI + JSON. MCP и HTTP API сознательно не делались (`docs/agent-graph-implementation-2026-10-21.md` §2) | РЕАЛИЗОВАНО (CLI) |
| RabbitMQ | Blueprint и lab-задел, discovery-профиля нет | ПЛАН |
| Многопользовательский режим, SSO, ACL | Нет. "один доверенный OS user, не изоляция SaaS tenants" | ПЛАН |

Тесты: 118 `def test` в `tests/graph/` (подсчёт по файлам 24.10.2026);
по отчёту пачки 1 на интегрированном main прошли 116 graph-тестов и 541 тест
ядра (`experiments/evidence_refs_v2/runs/2026-10-22-batch1/README.md`).

### 3.2. Демонстрационное приложение `src/agent_graph_demo`

Отдельное веб-приложение на русском языке: сервис Orders, сервис Status,
потребители Reporting, Billing, Export, Health; сценарий A→B→D→E с реальным
исполнением в Docker и проверкой множества из 250 ID
(`docs/agent-graph-demo/ACCEPTANCE.md`). Показывает выбранную связь, точный
фрагмент кода, условный риск, наблюдённый результат проверки и историю.

Статус: **СИНТЕТИКА**. Набор данных и сервисы написаны нами. Установлено
22.10.2026 на закрытую ВМ `dm-p1-ui`, backend слушает только `127.0.0.1`,
публичной ссылки нет, модель выключена (`UNAVAILABLE_NO_CALLS`)
(`docs/agent-graph-demo/deployments/2026-10-22/README.md`).

### 3.3. Реальная модель

Единственная живая серия: 22.10.2026, Cloud.ru Foundation Models, три
синтетических случая, две модели. Полный цикл прошли **2 из 6** сочетаний:
GPT OSS 120B на Reporting и Export; Qwen3-Coder-Next - 0 из 3. Контроль с
decoy (Status) не прошла ни одна модель. Стоимость серии около 2,58 руб.
(`experiments/evidence_refs_v2/runs/2026-10-22-batch1/README.md`).

Это проверка работоспособности протокола, а не качества продукта.

## 4. Что не проверено

Из собственных документов проекта на 22.10.2026:

- ни одного внешнего пользователя и реального случая клиента
  (G-01 открыт, `useful-graph-open-questions` §2.1);
- записей проведённых интервью в репозитории нет: есть сценарий
  (`docs/launch-2026-10/02-STAKEHOLDER-INTERVIEWS-RU-EN.md`) и шаблон заметок.
  Отсутствие записей в репозитории не доказывает, что разговоров не было;
- диагностическая серия из 12 задач против сильного coding agent с теми же
  доступами и заметками не проводилась
  (`agent-graph-implementation-2026-10-21.md` §6);
- критерий продолжения записан заранее: серьёзных пропусков не больше, чем у
  базового агента, и не менее 20% экономии полного активного труда
  (`product-architecture-roast-2026-10-20.md` §3). Он не измерен;
- дата пересмотра направления назначена на 27.10.2026
  (`product-focus-2026-10-20.md` §8).

## 5. Сильные стороны, подтверждённые кодом

Их немного, но они настоящие:

1. Дисциплина доверия. Статическая находка, кандидат модели, исправление
   человека, наблюдённая проверка и внешний отчёт хранятся как разные статусы
   и не сливаются в "успех". Это проверяется тестами, а не только описано.
2. Обнаружение связей из исходного кода, а не ручная регистрация. Карта
   строится без готовых рёбер, с decoy и явными пробелами.
3. Основание с точностью до байтов: digest файла, диапазон строк, версия
   снимка. Свежесть вычисляется, а не объявляется.
4. Анализ diff привязан к конкретному месту у потребителя, а не к схеме API
   вообще.

## 6. Слабые стороны, подтверждённые кодом

1. Охват: один язык, одна библиотека клиента, один фреймворк провайдера, три
   вида изменений. Реальный корпоративный код с обёртками над HTTP-клиентом
   и сгенерированными SDK в этот профиль почти не попадёт.
2. Нет подключения к реальным источникам: только локальные снимки.
3. Нет MCP, HTTP API, UI для графа вне синтетического демо, многопользовательского
   режима.
4. Полный пересчёт при каждом запросе.
5. Объём инженерной обвязки (CI, аудиты, ledger, приёмки) несоразмерно больше
   объёма продуктовой проверки на людях.
