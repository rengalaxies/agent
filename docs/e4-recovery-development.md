# E4-R: журнал событий и восстановление координатора

Дата: 2026-09-23. Продолжение E4 на синтетическом development-сценарии
T-03 с третьим доменом fintech. Команда запуска из корня проекта:
`PYTHONPATH=src python tools/run_e4_recovery.py`. Машинный отчет:
`results/e4-recovery-development.json`.

## Правила до проверки

Каждое входящее событие записывается в SQLite до подтверждения получения;
журнал привязан к конкретным `proposal_id`, `snapshot_id` и перечню доменов.
При восстановлении новый координатор перечитывает события в порядке записи.
Одинаковые повторы учитываются единожды; разные вердикты одного домена
переводят решение в `NEEDS_REVIEW`. Недостающий домен запрещает `ACCEPT`.
После атомарной финализации итог неизменен: поздний вердикт не меняет решение,
а требует отдельного предложения/ручного разбора. Параллельные финализаторы
сериализуются транзакцией SQLite. `REJECT` может быть вынесен до завершения
остальных доменов, если конфликтующих вердиктов нет.

## Полученные данные

- Координатор записал один вердикт, завершился с кодом 23 через `os._exit`,
  после чего новый запуск прочитал запись и получил `ACCEPT` от всех трех доменов.
- Повтор доставленного вердикта распознан: 4 записи в журнале, 3 уникальных
  домена, 1 повтор. Другой процесс повторно прочитал решение `ACCEPT`.
- Без mobility принято `NEEDS_REVIEW`. Повторный запуск с mobility не повысил
  окончательное решение до `ACCEPT`.
- Все 5/5 проверок драйвера прошли; конфликт, неверный снимок и несовместимый
  контекст журнала покрыты отдельными тестами `tests/test_journal.py`.

Вызов `PYTHONPATH=src python -m unittest discover -s tests -q` проверяет
регрессию всего прототипа. Это инженерная проверка механизма восстановления;
она не доказывает H3 для сети независимых серверов и не подтверждает H1.

## Границы

Журнал SQLite остается общим локальным ресурсом. При потере диска,
подмене файла, недоступности общей файловой системы или разделении сети
консенсус и перенос состояния не обеспечены. Хеш события не аутентифицирует
отправителя. Постоянное хранение с `synchronous=FULL` и WAL проверено в
тестовом окружении без отдельного испытания физического отказа питания.
Следующий этап - три среды с сетевым транспортом, индивидуальным состоянием
доменов и измерением задержек/отказов; выводы E3 остаются исследовательскими.
