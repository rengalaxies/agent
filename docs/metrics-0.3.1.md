# Зафиксированный статистический протокол 0.3.1

## Единица анализа и зависимость сценариев

Primary contrast - `V2` против `V1-ind` на одних и тех же сценариях. Единица наблюдения - сценарий, а не отдельный запуск режима. Сценарии одного семантического семейства используют общие правила генерации, один тип продукта и близкую логику обязательств, поэтому не считаются независимыми. Они имеют общий `cluster_id` в scoring-only каталоге. `cluster_id` отсутствует во входных YAML и не передаётся валидаторам.

Evaluation-набор содержит шесть кластеров F1-F6. В F1 и F2 находится по восемь сценариев, в F3-F6 - по шесть. Каждый кластер содержит опасные и допустимые варианты. Парность режимов задаётся общим `scenario_id`, а кластеризация учитывает зависимость сценариев внутри одного семантического семейства.

## Метрики режима

| Метрика | Определение |
|---|---|
| `exact_decision_accuracy` | Доля полных совпадений с глобальным эталоном |
| `dangerous_safe_detection_rate` | Доля опасных изменений, не получивших `ACCEPT` |
| `dangerous_strict_reject_rate` | Доля опасных изменений с точным решением `REJECT` |
| `unsafe_accept_rate` | Доля опасных изменений, ошибочно получивших `ACCEPT` |
| `admissible_accept_rate` | Доля допустимых изменений с решением `ACCEPT` |
| `false_block_rate` | Доля допустимых изменений с `REJECT` или `NEEDS_REVIEW` |
| `needs_review_rate` | Доля всех решений `NEEDS_REVIEW` |
| `consumer_decision_accuracy` | Доля совпадений локальных решений по потребителям |
| `median_latency_ms` | Медианная длительность принятия решения |
| `p95_latency_ms` | 95-й перцентиль длительности принятия решения |

Для `dangerous_safe_detection_rate`, `false_block_rate` и `needs_review_rate` публикуются 95% Wilson score intervals как описательные интервалы отдельных долей. Основной вывод о разнице режимов опирается на отдельный кластерный анализ по семействам.

## Парное сравнение

Для каждого опасного сценария рассчитывается разница индикаторов безопасного предотвращения релиза: `I(V2 != ACCEPT) - I(V1-ind != ACCEPT)`. Аналогично для допустимых сценариев рассчитывается разница индикаторов ложной блокировки.

Публикуются:

- разница `dangerous_safe_detection_rate`;
- 95% percentile cluster bootstrap interval по 10 000 перевыборкам целых кластеров;
- число парных улучшений и регрессий;
- точный двусторонний cluster sign-flip p-value;
- обычный точный McNemar p-value только как не скорректированная диагностическая величина;
- разница `false_block_rate` и её 95% cluster bootstrap interval.

Seed bootstrap и число перевыборок фиксируются в `experiments/analysis-plan-0.3.1.yaml`.

## Правило поддержки H1

H1 считается поддержанной только на запуске с `purpose: confirmatory_e3`, если одновременно выполнены все условия:

1. Разница `dangerous_safe_detection_rate` между V2 и V1-ind не меньше 0,15.
2. Нижняя граница 95% кластерного интервала этой разницы больше нуля.
3. Точный двусторонний cluster sign-flip p-value не превышает 0,05.
4. `false_block_rate` V2 не превышает 0,10.
5. `needs_review_rate` V2 не превышает 0,10.
6. На опасных сценариях нет парной регрессии V2 по отношению к V1-ind.

Порог 0,15 соответствует трём сценариям из 20 опасных evaluation-сценариев. Границы 0,10 соответствуют не более чем двум ложным блокировкам среди 20 допустимых сценариев и не более чем четырём `NEEDS_REVIEW` среди 40 сценариев. Это заранее выбранные критерии исследовательского дизайна, а не заявленные отраслевые нормативы.

Development-набор используется только для регрессионной проверки. Даже если его наблюдаемые значения проходят отдельные пороги, отчёт получает статус `not_assessed_development_only` и не может поддерживать H1.

## Ограничение вывода

Кластерные интервалы характеризуют устойчивость результата к составу шести зафиксированных семейств сценариев. При шести кластерах статистическая мощность и разрешение sign-flip теста ограничены; положительный вывод требует согласованного эффекта между семействами. Если ненулевой вклад имеют лишь три семейства, минимальное двустороннее p равно 0,25, так что целевой p <= 0,05 недостижим на таком результате. Порог 0,05 сохраняется как строгий ориентир, но его невыполнение означает отсутствие поддержки H1 по этому правилу, а не повод менять каталог после просмотра исходов. До freeze отдельно проверить достижимость, достаточность числа независимых семейств и необходимость альтернативного заранее объявленного описательного вывода. Интервалы не превращают авторский синтетический каталог в случайную выборку промышленных изменений и не подтверждают внешнюю валидность без независимой разметки.

## Аудит достижимости

[Аналитическая проверка](h1-feasibility-2026-09-29.md): при отсутствии регрессий p = 2/2^m, где m - число ненулевых семейных вкладов. Для p <= 0,05 требуется m >= 6. При шести семействах текущего плана положительный вклад нужен во всех шести; это проверка достижимости, не оценка мощности и не результат E3.
