# Data Mesh Release Protocol

Минимальный исследовательский прототип для ВКР "Проектирование событийно-ориентированной архитектуры управления кросс-платформенными метаданными пользователей на принципах децентрализации (Data Mesh)".

Текущий срез реализует только детерминированное ядро:

- форматы `ChangeProposal`, `ConsumerObligation`, `LocalVerdict` и `ReleaseDecision`;
- три синтетических домена: `fintech`, `retail`, `mobility`;
- режимы `V0`, `V1-ind`, `V1-oracle` и `V2`;
- 20 сценариев разработки шести семейств, включая 12 канонических;
- безопасную финализацию `REJECT > NEEDS_REVIEW > ACCEPT`;
- воспроизводимый `run_manifest` и машинно-читаемый отчёт.

В этот этап сознательно не включены Kafka, PostgreSQL, LLM-агенты и автоматический bootstrap. Они подключаются после проверки корректности ядра. Локальный исполнитель не имитирует распределённость и не используется как доказательство E4.

## Быстрый запуск

Требуется Python 3.12.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
make test
make pilot
```

`make pilot` прогоняет 20 сценариев через четыре режима и сохраняет:

- `results/pilot-results.json`;
- `results/run-manifest.json`.

## Структура

- `src/datamesh_release_protocol` - модели, валидаторы, конечный автомат и CLI;
- `scenarios/development` - 20 сценариев разработки;
- `contracts/base` - базовые продукты трёх доменов;
- `constitutions` - локальные полномочия и безопасное поведение;
- `policies` - федеративные инварианты финализации;
- `schemas` - JSON Schema ключевых артефактов;
- `tests` - функциональные и fail-safe проверки;
- `experiments` - конфигурация пилота;
- остальные каталоги зарезервированы для следующих этапов и содержат только пояснения границ.

## Интерпретация режимов

- `V0` проверяет совместимость структуры схемы.
- `V1-ind` применяет только явно объявленные воспроизводимые baseline-правила сценария.
- `V1-oracle` применяет вручную заданные предикаты ко всем предоставленным обязательствам и служит контролем чувствительности.
- `V2` общим интерпретатором сопоставляет новый контракт с типизированными обязательствами каждого активного потребителя.

Ожидаемая метка сценария не передаётся валидаторам. Она используется только внешним оценочным контуром после получения решения.

## Следующий этап

Версия 0.2.0 является внутренним кандидатом на заморозку: 20 сценариев разработки уже сформированы, но независимая экспертная проверка эталонных решений ещё не проведена. После неё реализации и правила замораживаются, а 40 отложенных сценариев E3 создаются отдельно и не используются для донастройки валидаторов.
