# Экспертный пакет expert-1

Откройте `questionnaire.html` в обычном браузере. Это автономная анкета на 80 заданиях: блок A - 40 evaluation-случаев по семантике; блок B - 40 заданий на development-примерах по достаточности карты. Она не отправляет данные; эксперт скачивает JSON и передаёт его исследователю самостоятельно. Промежуточный JSON можно загрузить обратно. Хранение в браузере автоматически не используется; при паузе нужно скачать черновик.

Каждый случай требует решения ACCEPT/REJECT/NEEDS_REVIEW, основания, уверенности 1-5 и отдельной оценки реалистичности 1-5. Для NEEDS_REVIEW обязательны недостающие сведения. Пакет разделяется на два блока по 40; внутри можно работать порциями по 20. Итого 80 решений, плюс 80 оценок реалистичности. В блоке B каждое из 20 development-изменений дано с полным и неполным контекстом карты; варианты одного изменения зависимы. Блок A служит проверке семантического эталона; блок B - проверке постановки полноты карты и не включается в основной E3. Время и утомляемость проверяются пилотом, не обещаются заранее.

## Протокол исследования

| Этап | Действие | Сохраняемый результат |
| --- | --- | --- |
| Пилот | 2-3 специалиста независимо оценивают первые 5-8 случаев; фиксируем фактическое время и неясности | Замечания, продолжительность, версия анкеты |
| Коррекция до freeze | Исправляем неоднозначные исходные условия; при изменении сценариев перестраиваем пакет и хеш | История изменений; новая версия каталога |
| Независимая разметка | Минимум 2 независимых эксперта на каждый случай; целевой набор около 10 разных ролей | Исходные JSON, роль, псевдоним, версии |
| Проверка | Валидируем согласие, полноту, уникальность и совпадение catalog_hash | Протокол принятых/отклонённых экспортов |
| Разбор расхождений | Два эксперта обсуждают основания; при неразрешённом споре третий эксперт принимает документированное решение | Исходные мнения, итог, основание, кто и когда согласовал |
| Freeze | Фиксируем согласованный эталон отдельно от входов V2 | Версии, manifest и независимая эталонная разметка |

Если случай нельзя однозначно разметить в рамках заявленной модели, его уточняют или заменяют до freeze с новой версией и повторной независимой оценкой. Не удалять неудобное расхождение после просмотра результатов режимов. Большая выборка экспертов улучшает оценку межэкспертной согласованности, но 800 решений по 80 общим заданиям не становятся 800 независимыми сценариями H1.

Сбор и анализ:

```sh
python expert/build_questionnaire.py --scenarios scenarios/evaluation --map-source scenarios/development --output expert/questionnaire.html
python expert/analyze_responses.py --exports /path/to/expert-a.json /path/to/expert-b.json \
  --catalog expert/questionnaire.catalog.json --output /tmp/expert-agreement.json
```

Анализ содержит отдельные разделы по блокам semantic_quality и knowledge_sufficiency; суммарный раздел лишь описательный. Анализ выдаёт голоса, сохранённые причины, расхождения и попарную долю согласия/Cohen kappa. Автоматического большинства как истинной метки нет. Kappa при вырожденном одинаковом распределении не определяется и возвращается null. Разметка и реалистичность не подтверждают H1 сами по себе.

Файл оценок хранить отдельно от публичного репозитория. Не запрашивать реальные пользовательские данные и корпоративные секреты. RU/EN текст приглашения остаётся в `docs/expert-outreach-2026-09-27.md`; публикация и отправка не выполнены.
